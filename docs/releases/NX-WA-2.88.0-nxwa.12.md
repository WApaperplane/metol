# NX-WA 2.88.0-nxwa.12 — 双 LUT 各自强度 / 16 键位实测

发布日期：2026-11-02
性质：功能版本。混合从「一个比例」变成「两张表各一个强度」，并把机身键位一次采全。

## 一句话

两张 LUT 可以各有各的强度了，而且不用新二进制 —— 归一加权的数学恰好等于现有的
`mix` + `strength` 两次调用；16 个实体键第一次全部采到（10-17 那条「方向键不可得」是
探针没抢到焦点），转盘的每格一个 `KeyPress`，能当连续调节器。

## 一、双 LUT 各自强度

「两个强度」有三种自洽语义，拿 68 张真实表实测后只剩一个能用：

| 模型 | 公式 | 实测 |
|---|---|---|
| M1 偏移相加 | `B0 + a(A−B0) + b(B−B0)` | a+b>1 时最多 **692/4913 节点越界**（14%），死黑死白 |
| M2 顺层覆盖 | `mix(mix(B0,A,a),B,b)` | 顺序敏感：A/B 互换平均差 **7 级**，双 100% 差 **28–30 级** |
| **M3 归一加权** | `B0 + (a(A−B0)+b(B−B0))/max(1,a+b)` | 零溢出、零顺序依赖 |

选 M3，并且发现它拆开就是现有两个动词：

```
s = min(a+b, 1)        r = b/(a+b)
M3 = B0 + s·(mix(A,B,r) − B0)      ← mix 一次，strength 一次
```

所以新增的只有一条 `lut.sh blend <A> <r> <B> <s>`，机内 `lutmix.arm` 一行没改，中间表走 `/tmp`。
qemu 下真跑两次调用，与两步参考逐字节全等，与理想单步差 ≤1 级（两次 8 位取整的极限）。

面板上是「两个强度各一根」：左右键切 A/B 焦点，滑杆与右上拨盘调当前那个，底部状态行
同时显示 `A 60%  B 25%  -> 比例 71% / 强度 85%`。

三种语义的完整数据与取舍：[`docs/current/DUAL_STRENGTH_2026-11-02.md`](DUAL_STRENGTH_2026-11-02.md)

## 二、16 个实体键全部实测

10-17 的结论「方向键与转盘在 X11 无事件，走 GPIO 私有通道」**是错的**。当年的探针是 1×1
override-redirect 窗口（为了躲黑屏事故），拿不到 `XSetInputFocus`，键被别的窗口吃了。
面板自己抢焦点，16 个键一个不缺：

| 物理键 | keysym | code |
|---|---|---|
| 上 / 下 / 左 / 右 | `KP_Up` / `KP_Down` / `KP_Left` / `KP_Right` | 80 / 88 / 83 / 85 |
| 中央 OK | `KP_Enter` | 104 |
| MENU / BACK | `Menu` / `KP_Delete` | 135 / 91 |
| 播放 ▶ / Fn | `XF86Tools` / `XF86HomePage` | 191 / 180 |
| EV 拨盘 ← / → | `XF86AudioPrev` / `XF86AudioNext` | 173 / 171 |
| 右上拨盘 ← / → | `XF86ScrollDown` / `XF86ScrollUp` | 186 / 185 |
| 模式拨盘 | `F9` / `F8` | 75 / 74（刻意不绑） |
| 半按快门 | `Super_L`（X11）= `event0 code 125` | 133 / — |

**转盘每格发一个 `KeyPress`，不是滚轮事件** ⇒ 能当连续调节器：EV 拨盘翻页，右上拨盘在
混合态按 5%/格调强度。

顺带修了 `keys.conf` 的一个真缺陷：原来只做追加，而 `keymap_action()` 取第一个匹配、
默认条目在前，所以「改一个已有键的含义」永远无效。现在同名 keysym 是覆盖，`none` 解绑。

## 三、机上修掉的五处

第一次在真机（192.168.0.104，SSH）上跑三条主线，暴露的都是「离线假树测不出来」的：

| # | 症状 | 根因 |
|---|---|---|
| 1 | 整库被替换、新条目丢失 | `order_sync` 用 `FNR==NR` 区分两个输入，第一个输入为空时误判到第二个 |
| 2 | 排序对 `warm_sepia` 无效 | BusyBox 1.20.2 的 `grep -x` 对完整行返回不匹配（普通 `grep -q` 能匹配） |
| 3 | 排完序重开还是旧顺序 | 启动器只盯 `looks/` 的 mtime，而排序只改 `state/order` |
| 4 | 恢复快照后 `recipes.txt` 少一条 | `restore` 直接 `cp` JSON，没有重新 export |
| 5 | 同一秒两次操作备份被覆盖 | 备份文件名精确到秒 |

## 四、面板交互：两次实机否决

| 尝试 | 结果 |
|---|---|
| 浏览态长按 = 标记 A/B | ❌ 一按整排就跳（列表是「选中项居中」的 5 项窗口，press 选中瞬间整排平移，手指底下换了条目），还把既有的长按进编辑态挤掉 |
| 左右滑动切项 | ❌ 与整排平移叠加，手指刚落下整排就动，再滑一次把目标甩掉 |

定稿：长按回编辑态、删掉滑动，翻页只剩滚条 / 上下键 / 两只拨盘。A/B 在混合态用按钮设。
滚条轨道上画 A（绿）/ B（橙）两个刻度，列表前置 `[A]` / `[B]`，跨页也看得见端点在哪。

## 六、安装与回退

与之前相同：解压到 SD 卡根 → 开机自动同步（`install.sh` 只覆盖不删，改了 `scripts/` 记得
先同步母本）。本轮改动文件：

| 文件 | md5 |
|---|---|
| `scripts/lut.sh` | `1d7bdd1a43b7e6eed76a6af9b6190da8` |
| `scripts/recipelib.sh` | `626ba2e07dddf8530802fb4bc06f9800` |
| `scripts/nxui/nxui.arm` | `4b6abaca741c04cb474aa160dd536fc3` |
| `scripts/lut/lutmix.arm` | `addae11303c911fe11ef7c48c01aa3c7` |

> 部署后必须 `chmod 755` 面板二进制 —— tar 从 Windows 打包会丢 x 位，`[ -x "$BIN" ]` 会让
> `nxui.sh` 静默不启动。哈希相同不代表能跑。
>
> 构建不可复现：同一份源码连编两次 md5 差 6 字节（`.strtab` 里 gcc 的临时目标名
> `ccXXXXXX.o`）。判部署漂移要 push 完立刻比，别拿昨天的哈希比今天重建的产物。
