# NX-WA 2.88.0-nxwa.9

发布日期：2026-10-20
上一版：2.88.0-nxwa.8

> **这是一个完整包**（解压到 SD 卡根即用）。如果你已经在 v8 上只差这两个 bug 修，
> 用配套的小补丁 [`LUT-FIX-20261020.zip`](#) 就够，不必整包重装。

## 一句话

**修好 v8 的两个「路径漏改」：Still（成片）有两条选表分支只改了一条，View4 四项只改了两项 ——
表现为「取景器有滤镜、照片没有」和「切到 AdobeRGB 就不生效」。**

两处都不是精度问题，是覆盖不全。修法是把 Still 的 6+12 项、View4 的 4 项**全部**指向工作槽。

## 1. 修了什么

| # | 症状 | 根因 | 修复 |
|---|---|---|---|
| A | 取景器有 LUT，拍出来的 JPEG 没有 | p7 的 Still 选表实现（`0x80382B30`）按 `+0x21` 走两条互斥分支：**屏幕色彩开启 → BV12 十二项**，关闭 → Still6 六项。v8 只改了 Still6 | apply 时 Still6 + BV12 一起写（各自备份、off 时各自还原） |
| B | 切到 AdobeRGB 后取景不生效 | View4 是**四项表**：`[0]` AdobeRGB+屏色开、`[1]` sRGB+开、`[2]` AdobeRGB+关、`[3]` sRGB+关。v8 只写了 `[1]/[3]` | 新增 `view-set` / `view-restore`，一次写全四项 |

附带修掉一个**静默半应用**：`still-set` 首次写要先把原厂六字备份到 SD，
若 `/mnt/mmc/nxwa_regtab_20261018/` 不存在则备份失败 —— 此时槽和取景已经改好、
只有成片那条没写。现在写前先 `mkdir -p`，失败也会明确报错而不是继续。

## 2. 为什么 v8 会「取景有、成片没有」

同一个设置位（`+0x21`，来自「屏幕色彩」）同时决定两件事：

| 屏幕色彩 | `+0x21` | View 读 | Still 读 | v8 覆盖情况 |
|---|---:|---|---|---|
| 关 | 0 | `View4[3]` | Still6（6 项） | 两处都改了 ✅ |
| 开 | 1 | `View4[1]` | **BV12（12 项）** | View 改了，**Still 漏** ❌ |

10-18 那轮「负片实验」之所以成功（成片真的变负片），是因为当时屏幕色彩是**关**的，Still 走 Still6。
同一份代码、不同设置，走的分支不同 —— 这是本次最值得记的一条。

判据工具：`sh /mnt/mmc/lut/still_probe.sh`（只读），会打印三张登记表、当前 OLED/色彩空间设置、
上次 apply 的日志，并直接给结论。

## 3. 换表流程（本版实际链路）

```
lut.sh apply <名>
  ├ 写 19,712 B 进 A18 (0x81119F00)      ← 槽内容
  ├ View4 四项 → A18                      ← 取景（sRGB/AdobeRGB × 屏色开/关 全覆盖）
  ├ Still6 六项 → A18                     ← 成片，屏色关时走这条
  └ BV12 十二项 → A18                     ← 成片，屏色开时走这条
（然后半按一次快门，让 p7 自己走完选表与装载）
```

`off` 把四张登记表全部写回原厂 + 还原 A18 槽内容。

## 4. ★ 这个 mod 的界限

写清楚比写得好看重要。下面每一条都对应一次实机或静态验证，没有"应该可以"。

### 4.1 平台

| 项 | 状态 |
|---|---|
| NX500 + 固件 **1.12** | ✅ 全部功能在本机验证（A2 补丁镜像 `712c6fd0…`） |
| NX1 + 固件 1.41 | ⚠️ 可安装，**LUT / FilmLab 未在 NX1 上验证**；NXUI 自动回退社区原版 |
| 其它固件版本 | ❌ 安装脚本直接拒绝 |
| 安装形态 | **完整包**：自带 `scripts/` 全套（NX-KS2 2.88 + Metol 扩展，267 个文件）与 `patch-a2/` 补丁镜像，首次插卡自动**全量安装**到 `/opt/usr/nx-ks/`，**不需要另外先装 NX-KS2**；已装机器插卡走增量同步（只覆盖不删除） |

### 4.2 色彩：sRGB 可信，AdobeRGB 只保证"生效"

| 项 | 状态 |
|---|---|
| sRGB 输出 | ✅ 取景与 JPEG 成片都按同一张表处理，颜色可信（45 张随包表的基准） |
| AdobeRGB 输出 | ⚠️ **会生效，但颜色未标定**。表按 sRGB 坐标生成（轴序 R/G/B、中性点 128），JPEG 却带 AdobeRGB profile ⇒ 同一张表在两种空间下观感不同 |
| 智能滤镜（相机原生滤镜枚举 14–18） | ❌ 走另一条动态 24 档路径，本 mod **不覆盖** |
| RAW（`.SRW`） | ❌ **不承诺被 LUT 烘焙**。目前只验证 JPEG 成片 |
| 视频 | ❌ 不在本版范围 |

### 4.3 生效方式

| 项 | 状态 |
|---|---|
| apply 后要**半按一次快门** | ✅ 必须。软件触发重载的入口还没找到，唯一可靠触发点是 p7 自己的半按事件 |
| 看到变化才叫成功 | ✅ 日志全绿不等于画面变了 —— v7 就栽在这（回读值正确但 ISP 没重读表） |
| 开机即生效 | ❌ 全部写入是 RAM 操作，**断电/重启回到原厂**（要持久化得改固件镜像，不在本版） |
| 不刷机、不改分区 | ✅ 只写 `/dev/mem` 里的 16 KiB 代码区与一个空闲槽，可双向回滚 |

### 4.4 它不是什么

- **不是完整的色彩管理**：不做输入/输出 profile 转换，LUT 只是 ISP 里的一个 3D 查找表。
- **不是"所见即所得"的承诺**：取景器与成片用同一张表，但相机内部对两者的处理链不同（这也是为什么两条链要分别重定向）。
- **不接管相机 UI**：NXUI 是相机自带 X11 上的一层，不改原厂菜单行为。
- **不是破解/去限制**：没有解除区域锁、没有改录制时限、没有绕过保修 —— 它是在已有的 NX-KS2 框架上加深 LUT 与配方能力。

### 4.5 风险与回滚

- 写的是**内存**，不是固件分区。断电、取出电池、重启相机 = 回到原厂状态。
- 唯一需要小心的操作是**自己裸写 3D LUT 配置寄存器**（`+0x00C` + 脉冲）—— 那会让 ISP 读到原厂时序之外的地址，表现为严重偏色花屏。本 mod 从不这么做，重载一律交给半按。
- `lut.sh off` 会把四张登记表与 A18 槽还原；原厂备份存在 `/mnt/mmc/nxwa_regtab_20261018/`。
- 后果自负：这是给愿意读日志、能接受「某一版不好用」的人用的东西。

## 5. 安装

解压到 **SD 卡根**（`info.tg` `nx_cs.adj` `install.sh` `scripts/` `looks/` 就位）→ 插卡自动安装 →
**手动开一次蓝牙**（开机钩子靠它初始化）。细节见 [SYNC.md](SYNC.md)。

补丁版（已在 v8）：把 `LUT-FIX-20261020.zip` 里 4 个文件投到 `/mnt/mmc/lut/` 与 `/opt/usr/nx-ks/lut.sh`，
`md5sum nx_regtabwrite.arm` 应为 `a1db60c1aa2673951e8e4e52f4d5076b`。
