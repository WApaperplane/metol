# NX-WA 2.88.0-nxwa.13 — 视频 LUT 自动联动

发布日期：2026-11-07
性质：功能版本。3D LUT 从「取景 + 照片」扩到录像：**开录首帧就带表**，且不需要第二个开关。
**本版只新增这一项功能**；2.5K、10 bit / 内置 gamma 两节是核对与否证，不是新能力。

## 一句话

`lut.sh apply` 之后直接按录像键，**第一帧就是 LUT 色**，`lut.sh off` 自动停。
不靠开录后补写 —— p7 自己的 23 项档位指针表被整体指到用户表所在的 A18。

## 一、开录首帧：改 p7 的档位指针表

录像启动时 p7 会把 3DLUT 的 `LUT0` 指向它自己的内置档位表，不是用户的 A18。
第一次的做法是「预置 p7 会用的那个槽」，**失败了**：

| 段 | 开录时 `LUT0` | 结果 |
|---|---|---|
| `SAM_0319/0320` | `0x81158C00` | 预置该槽后，下一次开录被换到别处 |
| `SAM_0334` | `0x8113BE00` | 首 5 帧仍是内置表 |

⇒ **p7 选哪一档随场景变，写死单个槽必然漏。**

根因在 p7 数据段 VA `0x80383A28`（`p7_wrapped.elf` file `0x384a28`）：

```text
23 项 × 4B = 92 B，尾项后紧跟 e12fff1e（bx lr）—— 长度可判，不会越界
81145800 810d6900 810d1c00 810f8400
81158c00 810e9d00 81153f00 810c8200
810c3500 810db600 8113be00 810e0300
81140b00 810ccf00 81128a00 810f3700
8114f200 81137100 81132400 81123d00
810e5000 8114a500 8112d700
```

观察到的 `0x81158C00`（第 5 项）和 `0x8113BE00`（第 11 项）都在表里。把 23 项**一次全写成
`0x81119F00`（A18）**，p7 无论选哪一档，读到的都是用户的表。

`di-camera-app` 里 `0x2082b00c` 零命中 —— 这个切换是 p7 做的，用户态拦不到，所以只能改数据。

新增 `scripts/lut/nx_lutptr.arm`（地址与长度写死，`set` 后回读校验；
`save` 只在当前表不是「全 A18」时导出，防止把改过的表当原值），`lut.sh` 已集成：

```sh
sh /opt/usr/nx-ks/lut.sh apply warm_gold   # 写 A18 + 备份指针表 + 23 项全指 A18
# 直接按录像键，首帧即带 LUT
sh /opt/usr/nx-ks/lut.sh off               # 先恢复指针表，再还原 View4/Still6/A18
sh /opt/usr/nx-ks/lut.sh status            # 多一行 VIDEOPTR
```

改的是 RAM，**重启自动回原值**；每次开机首次 `apply` 时 `save` 会重新抓一份当前（原厂）表，
备份始终有效（`/mnt/mmc/lut/state/lutptr.bak`）。

## 二、自动联动：apply 即开，off 即停

`scripts/lut_video.sh` 是兜底：录像开始时按相机进程持有的**可写 MP4 描述符**（`l-wx` + DCIM）
识别，等 EP 完成中断（实测 1.2–6.8 ms 返回）后再补一次加载。指针表生效时它一次都不会触发。

| 设计点 | 为什么 |
|---|---|
| 用真实 MP4 写句柄判断在录 | 时间窗猜不准，开机/回放也会开 MP4 句柄 |
| 开录后 400 ms + 连续采样稳定检查 | 初版首次开录撞上一次超时，重试才成功 |
| 只认**本次开机** View4 四项都指向 A18 | 防止沿用重启前卡上的 ACTIVE 标记，把表写进错槽 |
| 控制锁 / 监视锁 / 加载锁分开 | 重复 `apply` 不打架，PID 保持不变 |
| 状态全在 `/tmp/nxwa-lut-video` | 重启即失效，不会带病启动 |
| 连续两次失败就退出 | 不留下一个反复写寄存器的死循环 |

### 加载协议（`scripts/lut/nx_lutload.arm`）

1. 仅 NX500 / 1.12，单次加载只接受 A17 / A18 / A19，未知 Cfg 直接拒；
2. 使能 EP 的 `EP_K_INT_ACC_3DLUT_RD_FINISH=7`，注册等待队列；
3. 写地址、格式、通道，`+8 bit8` 置位再清零；
4. 等驱动完成中断（500 ms 超时），随后退出访问模式；
5. **超时返回 `errno 110`，绝不记成成功** —— 失败也清访问模式。

## 三、边界

指针表方案解决了两条旧缺陷，但都不是「测过就算」：

| 旧现象 | 现状 |
|---|---|
| 首几帧是内置表色 | **已解决**：`SAM_0335` 179 帧零跳变（见验证） |
| 录像中途换表出现约 2 秒纯灰帧 | **机制上消失**（不再需要实时重载），但**未专门复测**。`SAM_0325` 记录的 3.0–5.0 s 全灰 9 帧仍可作为旧版行为的证据 |

仍未覆盖：长录（最长只测到 8.085 s）、更多帧率、快速状态竞争、面板内直接开关、其它拍摄模式。

**有代价要讲清楚**：23 个内置档位现在全被 A18 覆盖，相机自带的风格/智能滤镜会失去区分；
改的是 p7 运行时数据段，不是官方接口 —— 写错只会颜色不对，不写固件，重启即恢复。

## 四、核对：2.5K 映射是原版就有的，不是本版功能

先把计价方式说清楚：**2.5K 不是本版新增**。上游 NX-KS 的 `resup` 早就有 `2K` 分支，
`res_UHD2K.sh` / `off_res_UHD2K.sh` 也一直在，改的正是下面这两条立即数：

```text
0xe4428: 878ea0e3   # height 2160
0xe442c: 0faca0e3   # width  3840
```

上一轮还误判过一次「取消勾选没有恢复动作、必须重启」—— 核对后发现 `off_res_UHD2K.sh`
一直在跑 `resup UHD UHD`，该判断已撤回（见 [`RES25K_TOGGLE`](../current/RES25K_TOGGLE_2026-11-07.md) 文首纠错块）。

本轮对它**没有功能增量**，只有三件配套：

| 做了什么 | 性质 |
|---|---|
| SIFT + RANSAC 实测这个档位到底看到多少画面 | 新数据 |
| `gui_res.NX500` 文案改成「<档位>档 → <目标>（尺寸）」 | 文案 |
| `res_25k.sh`（带 `status` 的双向开关） | 诊断工具；确认菜单已有 off 脚本后不作为入口 |

实测（照片与两段视频统一 1600 px 宽做单应配准）：

| 模式 | 照片宽度覆盖 | 照片高度覆盖 | 内点 | 中位重投影误差 |
|---|---:|---:|---:|---:|
| UHD | 59.43% | 50.11% | 304 | 0.292 px |
| 2560×1440 | **98.79%** | 83.34% | 511 | 0.311 px |

「片门全开」这个说法只对**视角**成立，且要说准：这是接近照片全宽的 **16:9** 视角，不是完整
3:2 open-gate（上下仍裁）。传感器读出方式、跳行合并、混叠、滚动快门、动态范围均未确认，
不能拿输出尺寸反推读出。

## 五、菜单文案的实际改动

`scripts/gui_res.NX500` 原来写「UHD映射为2K」「DC映射为UHD」，主语宾语不明，用户分不清是
改录制档还是改屏幕。现在统一成「**<档位>档 → <目标>（尺寸）**」，两组各三行按档位排。
只改字，不改任何脚本行为。

## 六、两条否证（这版为什么不做 log / 10bit）

| 检查 | 结果 |
|---|---|
| 码流 `hvcC` | `profile_idc=1`（Main）/ `bitDepthLuma=8` / `4:2:0` / L5.1，无第二组 SPS |
| 全固件 352 MB 搜 `Main10` / `profile_idc` / `bit_depth_luma` | **0 命中** |
| `hvcC` 出现位置 | 仅 `mp4_parse_hvcC` —— 解析器，不是生成器 |
| `MOVIE_GAMMA_CONTROL`（0x760000） | 可写可逆，但 `IQ[180]` 恒为 `NORMAL/0`，画面无差异；app 侧 393 条 MOVIE 字符串**零 gamma** |

⇒ 8 bit 容器里做曲线重映射只能重分配 256 级码值，不产生动态范围。**log 在 NX500 上不可达**，
末端 3DLUT 重映射是唯一真实可用的色彩通道。

## 八、安装与回退

与之前相同：解压到 SD 卡根 → 开机自动同步（`install.sh` 只覆盖不删）。本轮改动文件：

| 文件 | md5 |
|---|---|
| `scripts/lut.sh` | `58797e50ff908d5161bb271fd5fa8fa2` |
| `scripts/lut/nx_lutptr.arm` | `38c12eb1f6d73589f1a89121933c5503` |
| `scripts/lut_video.sh` | `e6e93fce095e1d26037832a1757ff341` |
| `scripts/lut/nx_lutload.arm` | `d975e86da2dc2f543c1f51663b70dcea` |
| `scripts/res_25k.sh` | `f13deb28f5ac0f19496e2928b9f7b051` |
| `scripts/gui_res.NX500` | `ebb7ce80a9f8cf9d7d9f88246042e325` |

> `.arm` 是 zip 里的普通数据，解压到 SD 会丢可执行位；`install.sh` 对 `/opt/usr/nx-ks` 下
> 所有普通文件 `chmod +x` 兜底，漏了这一步的表现是 `lut.sh apply` 报
> `ERR nx_lutload.arm is missing` 或 `VIDEOPTR` 一行缺失。
>
> 构建不可复现：两个 `.arm` 每次重建 md5 都会变（`.strtab` 里的临时目标名），
> 判部署漂移要在 push 完立刻比，别拿昨天的哈希比今天重建的产物。

回退：`sh /opt/usr/nx-ks/lut.sh off` 会先恢复 p7 指针表、再还原 View4/Still6/A18；
只停录像监视用 `lut.sh video off`；整包回退覆盖旧版 `scripts/` 即可。断电/重启也会把
p7 数据段恢复成原厂值，无固件改动、无分区写入。
