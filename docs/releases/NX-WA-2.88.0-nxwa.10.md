# NX-WA 2.88.0-nxwa.10 — LUT 色彩体系重建

发布日期：2026-10-25
性质：色彩专项版本。引擎、度量、方案、清理四件事一起改，并撤回上一版的一部分错误结论。

## 一句话

LUT 偏色的根因是**三层独立缺陷叠加**（编码 / 色域 / 模型），不是参数没调好；
修好之后重建了度量，清理了 27 张同质表，新增 19 张有量化验收的色彩方案。

## 一、三层根因

| 层 | 缺陷 | 后果 |
|---|---|---|
| 编码 | RGB 设计表被按 Cr,Cb,Y 消费 | 全色错位，PC 预览正常、上机失败 |
| **色域** | 17³ 的 Cr,Cb,Y 网格 **80.5% 落在 sRGB 外**，Y=0 与 Y=255 平面合法率各仅 0.3% | 暗部/高光的有色格点由错误邻居插值而来 → 高光暗部不自然 |
| **模型** | 加性感知调色（S曲线+HSV饱和+Lab分离色调+加性fog） | 品红=R、B 同抬而 G 不动，加性偏移**必然**如此；灰进不出灰，黑位发纯红/纯蓝 |

旧表实测：中性轴最大色度差 66.73；26 张表黑位色度 >8，`kodak_kchrome25` 黑位
**19/0/2 纯红**、`cool_arctic` **0/4/16 纯蓝**；对照三星原厂三张全部 0.00。

## 二、度量重建（本轮最重要的修正）

`rgb_to_lab()` 的 sRGB→XYZ 矩阵乘反了，导致中性灰算出 a\*=−54.5、纯白 L\*=107。
这是个连续单调变换，所以**距离排序大体保留**（清理方向没错），但**所有色相与彩度的
绝对值都是假的**。已修，并用已知色块验证（白 100/0/0、灰 53.6/0/0、肤色 +12.1）。

连带修第二个：`shadow_tint` / `high_tint` 原在 L\*=0 与 L\*=100 处读 b\*，而 `grade()`
的 `endpoints` 在两端的把染色淡出为零，两个指标同时退化成 `−b*(中灰)`——同一个数
算了两遍。改为在输入 45 / 128 / 210 三点读取，并补 `shadow_a` / `high_a`。

**修正后的库真实形状**（不含新增批次）：

```
warmth      -2.3 .. 11.0      saturation   0 .. 38.8
shadow_a    -2.0 ..  2.2      high_a      -1.3 ..  2.5
```

**真正的短板是绿-品红轴几乎没用过**（±2 以内），不是冷暖不够。这是"理光蓝不蓝、
佳能红不红"的坐标证据。

## 三、清理：90 张只有 32 种外观

72 探针 + 21 灰阶 + 8 实景色，两表中位 ΔE00。90 张 4005 对，p50=6.41，16% 低于项目
门槛 3.112，7.8% 连人眼 JND（2.3）都够不上。单链接聚类会因链式效应把 72 张并成一簇，
改用**完整链接**：90 张实际只有 **32 种可区分外观**。

按 1.5 保守清理，保留项人工裁定（算法用"名字短优先"会想删 Portra 400 留 Leica M9）：

- 本地 `looks/` 102 → 75（27 张移入归档，非删除）
- 机端 72 → 54
- 中位 dE00 6.41 → **8.94**，JND 内 7.8% → **2.6%**

## 四、新增 19 张方案

### 12 张补坐标空白（`gap_`）

每张只在一个轴上走极端，因此彼此天然远离。双重门槛（对现有库 >3.112 且互相 >3.112）
12/12 通过：`low_key_warm`（压白点到 85.7）、`high_key_cool`、`nordic_overcast`
（warmth −12.1）、`cold_archive`、`fog_flat`（contrast 0.41）、`press_hard`、
`silver_retain`、`chrome_vivid`、`expired_1970s`（黑位 34.8）、`desert_noon`、
`neon_night`、`magenta_shadow`（a\* 正向，全库此前从未有）。

### 7 张品牌/色系（`brand_`）

按"名字承诺的颜色有没有真的动"验收，7/7 通过：

| 方案 | 特征实测 | 基线 |
|---|---|---|
| 理光蓝 | 蓝色相 291 → **278.9**，a\* 23.8→<20 | 291 |
| 佳能红 | 红彩度 72.4 → **84.7**（+17%），色相 27.2 | 72.4 |
| 宾得正负逆冲 | 阴影 −8.6 / 高光 +10.1，阴影带绿 a −3.9 | 0/0 |

| 青橙 | 阴影 −12.7 / 高光 +13.3（**全库最强分离**） | −10.7/+11.7 |

| 冷艳 | warmth −6.7 且 sat 36.8 | — |

### 两条先探明的硬约束

1. **蓝的"更青"与"更浓"在 sRGB 里互斥**：`sat_hues{'240'}`=1.6 时 C\*=77.9，推到 2.6
   反而跌回 71.4（色相往青必须压 a\*，绿一多蓝就不纯）。理光蓝因此锁定"色相更青"。
2. **高光染色量由中灰与高光的 b\* 差决定**，不看高光绝对值（mid10/hi13→3.1，
   mid3/hi18→12.5）。金黄的暖度必须由阴影段承担。

## 六、撤回与未解决

- **撤回**上一版"库是窄带、warmth 只有 0.4~11.8、没有偏冷的表"。那是在错空间里算的。
- **撤回**上一版"分离色调幅度都很小"。两个指标测的是同一个量，见第二节。
- 上一版 12 张 `gap_` 是在错误坐标下设计的，实测算出 warmth −12.1~+15.9 比原库极值
  还远，"填空"碰巧成立但不是有意为之，需按新坐标重标目标。
- 强偏色方案（青橙、逆冲、金黄、霓虹）只在柜子/玩偶/白墙上验过，**天空、植被、
  人像肤色未验**，青橙最容易在人像上翻车。
- 宾得正负逆冲是方向性近似，不是 E-6/C-41 化学过程串联的物理模拟。
- 理光蓝、佳能红是参考风格设计，不是原厂 profile 反解（原厂未公开三维映射）。
- 相机 JPEG 传递曲线仍未实测，`tone_strength` 是权宜近似。
