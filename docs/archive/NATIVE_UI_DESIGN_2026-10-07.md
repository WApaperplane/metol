# 原生 UI 方案 — 从 mod_gui 文本菜单到 EFL 控件树

> 2026-10-07 · 定位：**实现方案**，输入 `docs/{STRATEGY,FEATURE_MATRIX}_2026-10-07.md`。
> ★ 核心判断：**这是"取代"而非"迭代"** —— mod_gui 只4 种控件、点击即退、波轮不认键，
> 结构性做不到的事不能靠改配置解决。

---

## 0. 一句话设计原则

> **mod_gui 是"给命令套选择器"，原生 UI 是"把参数直接摆出来"。**
>⇒ 前者的天花板是「用户能选什么」，后者的天花板是「用户能调什么」。

---

## 1. mod_gui 的结构上限（不可协商的证据）

反汇编 `scripts/mod_gui`（14130B）得到的约束清单：

| 约束 | 证据 | UI 后果 |
|---|---|---|
| 只有 4 种控件 | `elm_win`/`elm_table`/`elm_button`/`elm_check` | 无滑块、无列表、无输入框、无图片 |
| 2 列固定网格 | 只调 `elm_table_pack` | 每页 ~12 项封顶 |
| 点击即退出 | rodata `Exiting the app.` + `elm_exit` | **无法连续对比** |
| 动作只能是命令 | 全部 `system("%s &")` | **无法表达"参数=值"** |
| 标签 ≤6 全角字符 | `---- 一键配方 ----` 被挤成 `一 键...` | 横线装饰一律不用 |
| 波轮键处理 | `key_down` 只认 4 keysym（Super_L/Super_R/Menu/XF86PowerOff），方向键落 else → `quit_app` | ★ mod_gui 不支持波轮；★ 波轮实际发什么键**待上机** |

⇒ ★★ **凡"选预设"用 mod_gui 够用；凡"调参数"必须自己写。**
⇒ ★★ 这条分界线直接决定了下面的功能分配。

## 2. 控件映射：把 4 个菜单页重画成控件树

### 2.1 信息架构**不变**，只换渲染方式

★ **决策：不重新设计信息架构**。现有 4 页结构（主/实用/对焦/系统）是被实机验证过的，
改架构的风险 ≫ 收益。只把每一页的**渲染载体**从「文本按钮」换成「控件」。

```
主菜单 gui_tpl.NX500
├── 胶片配方 FilmLab        → L2 配方页（elm_list + 缩略图 + 详情）
├── 实用功能               → L2 功能页（elm_switch 组，替换 10 个 checkbox）
├── 对焦 & 配置文件        → L3 保留 mod_gui（这些是一次性动作，不是参数）
├── 系统设置               → L2 设置页（elm_switch 组）
├── ★★ 实时调色           → L2 ★ 新增：elm_slider ×7（PW 7 维）
├── ★★ 内置色彩           → L2 ★ 新增：elm_radio ×4（4 档）
└── ★ 诊断/固件           → L2 独立页 + 二次确认（高危隔离）
```

★ **对焦/配置文件页保留 mod_gui**：focus_stack / profiles 都是**一次性动作**，
不是连续参数 ⇒ 文本按钮完全够用，不必重写。

## 3. ★★★ 头号设计决策：CJK 字体

### 3.1 问题

`/usr/share/fonts` 无中文字体（`nxfilmui.c` 已降级为 ASCII）。
⇒ ★★ **现有全部中文菜单标签（`延时摄影`/`实用功能`/`胶片配方`…）在自建 UI 里会渲染成空白。**
⇒ ★★ **这不是"细节问题"，它决定整个 UI 的文案语言。**

### 3.2 三个方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A·ASCII 英文** | 全部标签改英文 | 零成本、零风险 | 社区用户是中文语境，体验倒退 |
| **B·自绘点阵** |复用 `font5x7.c`（95 ASCII 字模）扩展中文 | 无依赖、体积小 | ★ 需手工做 200+ 汉字点阵 |
| **C·内嵌 TrueType** | 从PC 侧渲染 CJK 字形成位图，嵌进二进制 | 视觉最佳 | 需PC 渲染管线 + 体积 |

### 3.3 ★ 建议：先A 验证链路，再按需上 B

```
阶段 1（验证）：ASCII 标签。目标不是好看，是验证 EFL 窗口/波轮/触摸/CPU 四件事。
                ⇒ 零额外风险，一份 41KB 产物就能回答全部 4 问
阶段 2（产品）：若需中文，走 B（自绘点阵）
                ★ 现成资产：test_server/filmsim/src/font5x7.c 的点阵生成经验可复用
                ★ 只需覆盖 UI 用到的 ~80 个汉字，不是全字库
```

★★ **不要在阶段 1 就投入中文** —— 那会让"验证链路"和"做产品"两件事耦合，
一旦 EFL 路线本身有问题，中文字体就是白做的。

## 4. ★ 交互模型：三通道并行

| 通道 | 动作 | 映射 | 用途 |
|---|---|---|---|
| **波轮** | 上下 | `JOG1_CW/CCW` 或 `Up/Down` | ★ 切配方 / 调滑块（**主通道**） |
| **触摸** | 点/拖 | `elm_gengrid` item cb | 直接选/直接调 |
| **按键** | 确认/返回 | `KP_Enter` / `Left` / `XF86PowerOff` | 应用 / 退出 |

### 4.1 ★ "滚动即应用"是刻意设计，不是偷懒

单核相机上一次 `apply` 要走 7 次 `prefman set` + 强制 ISP 重读 ≈ **1–2 秒**。
⇒ **同步应用**（转到哪生效哪）比"选完再确认"好，因为用户转波轮的直觉就是"我在预览"。
⇒ 代价：转太快会在 `system()` 上排队 ⇒ ★ **必须加节流**（转过 1 格立即应用，
　 停在同一格 >300ms 才算稳定）。

### 4.2 ★ 光标必须可见

`paint_sel()` 已实现（选中=琥珀 255,200,80 / 其余灰 200,200,200）。
⇒ **单屏 9 个配方用波轮是盲操作**，没有高亮用户不知道自己选的是哪个。
⇒ ⚠️ 判空必需：`elm_gengrid` 滚动会懒回收 item，句柄可能变 NULL。

## 5. ★ 高危操作隔离（N07）

固件刷写这类操作**绝不能**和日常调色混在一个界面里。四道隔离：

| 措施 | 实现 |
|---|---|
| **物理隔离** | 独立页，不在主菜单露出（现有设计：进页才见） |
| **门控** | 页显示以 `p7flash.ok` 标记文件为条件（安装成功才出现） |
| **二次确认** | `elm_entry` 输入确认词，不用 yes/no 按钮 |
| **只读优先** | 状态页先只读显示（版本/校验和/是否官方原版），写操作在下层 |

★ **`gui_exit.sh` 已有正确行为**（killall mod_gui + 恢复 SYSTEMFREQENCYSTATE），
新 UI 的退出路径必须照抄这套收尾，否则相机可能卡在异常状态。

## 7. 反模式清单（明确不做）

| 不做 | 理由 |
|---|---|
| ★ 重设计信息架构 | 现有 4 页已被实机验证，改架构风险 ≫ 收益 |
| ★ 阶段 1 就做中文字体 | 会把"验证链路"和"做产品"耦合 |
| ★ 用 X11 做原生 UI | 已实机证伪：满屏吃满单核，连 `echo` 都跑不完 |
| ★ 链接期 stub 给 `ecore_*` | 符号被静态解析 → 真机调到空函数 → **波轮无反应且不报错** |
| ★ 凭记忆写 EFL 声明 | 铁律 84：只认白名单 |
| ★ 用 `elm_win_fullscreen_set` | 真机查无使用证据，满屏靠 `elm_win_resize_object_add` |
| ★ 在 UI 里"猜"参数是否生效 | 必须回 `iqr` 看，UI 只负责显示不负责判定 |
| ★ 把固件刷写和调色放同一页 | 高危必须隔离（铁律：破坏性操作独立+二次确认） |
