## 1. F1 —— P1 阻塞已静态解决（本次最有价值的产出）

### 1.1 机制（从 `scripts/keyscan` ELF 静态提取，非猜测）

`keyscan`（603448B）的 rodata 里有完整键名表，位于 `0x79cc0`–`0x79da8`：

```
EV OK PB FN DEL UP DOWN LEFT RIGHT AEL MOBILE S1 S2
MODE_SAS MODE_SCENE MODE_AUTO MODE_P MODE_A MODE_S MODE_M MODE_C MODE_C2
TOP_LCD EVF SS CN CH TIMER BRACKETING WB ISO AF METERING FRONT LK KK
                                                       ← 共 36 个有表项的键
```

三条触发规则（`FILMLAB_ONEKEY_UI.md` 从 keyscan.c 源码查证）：

| 规则 | 格式串 | 触发条件 | 生成文件名 |
|---|---|---|---|
| **A** | `EV_%s` | 按住 EV + 任意键 | `EV_<NAME>.sh` |
| **B** | `%s_%s` | 同一键 1 秒内连按两次 | `<NAME>_<NAME>.sh` |
| **C** | `%s` | MODE_SAS 转盘**松开**时 | `<NAME>.sh` |

★ 门槛 `strlen(shell_name) > 4`。
★ **无表项的键**（`REC` / `MENU` / `JOG1-3`）名字是空串 ⇒ 触发条件失败 ⇒ **不可用**（此前的猜测被证伪）。

### 1.2 已占用 vs 空闲（精确计算）

**当前实际占用**（`scripts/` 与 `scripts/nx-rc/` 交叉核对）：

```
EV_AEL.sh  EV_DOWN.sh  EV_EV.sh  EV_LEFT.sh  EV_MOBILE.sh
EV_OK.sh   EV_RIGHT.sh EV_S1.sh  EV_UP.sh          ← 9 个（★ 文档只记了 4 个）
nx-rc: EV_FLAB.sh  EV_FLAB_GUI.sh  MOBILE_MOBILE.sh
```

**★ 空闲的 `EV_<x>` 槽位（27 个）**：

```
EV_PB  EV_FN  EV_DEL  EV_S2  EV_MODE_SAS  EV_MODE_SCENE  EV_MODE_AUTO
EV_MODE_P  EV_MODE_A  EV_MODE_S  EV_MODE_M  EV_MODE_C  EV_MODE_C2
EV_TOP_LCD  EV_EVF  EV_SS  EV_CN  EV_CH  EV_TIMER  EV_BRACKETING
EV_WB  EV_ISO  EV_AF  EV_METERING  EV_FRONT  EV_LK  EV_KK
```

**★ 空闲的双击槽位：36 个键全部可用**（`LK_LK` / `WB_WB` / `ISO_ISO` / `AF_AF` / `FN_FN` …）

### 1.3 推荐方案（按体验排序）

| 优先级 | 槽位 | 触发 | 理由 |
|---|---|---|---|
| ★★★ **首选** | `FN_FN` | 双击 Fn 键 | Fn 是功能键、不参与拍摄、单手可达、零冲突 |
| ★★ 次选 | `LK_LK` | 双击 Lock 键 | Lock 键在拍摄中语义弱，同样单手 |
| ★★ 次选 | `EV_AF` 或 `EV_FN` | 按住 EV + AF/Fn | 沿用「EV+键」既有肌肉记忆（EV_MOBILE 已在用） |
| ★ 备选 | `EV_WB` / `EV_ISO` | 按住 EV + WB/ISO | 语义上"调色"最贴切，但这两键在拍摄中高频使用 |

⇒ ★★ **结论：P1 不再需要"上机查表"**。`keyscan` 的键名表已给出全部可用槽位，
　 只需在**下一次上机时**（与 P2~P7 合并）用 `debug` 参数实测目标键的 `code` 是否真的发得出来。
　 ★ 唯一残余风险：某个键**在硬件上不发事件**（如 `EVF` / `TOP_LCD` 在 NX500 上可能无实体键）。
　 ⇒ **FN / LK 有实体键，风险最低。**
