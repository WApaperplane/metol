## 1. 项目全景

### 1.1 平台

```
SoC：DRIMe5（双核）
├─ Linux 侧（ARM / Tizen，rootfs 只读 96% 满）—— di-camera-app 等全部用户态
└─ p7 侧（Cortex-A9 RTOS = T-Kernel 2.01.03，固件 12,075,648 B，VA 基址 0x80000000）
   通信：drime5_ep（中断）/ d5_sma（144 MB CMA @ 0x94000000）/ MCB（多核桥）
```

★ 10-12 新增旁证（`st cap ref tsk` / `ref mem`）：
- p7 运行时内存：**任务控制块 EXINF 在 `0x8141xxxx`**、**任务栈在 `0x8182xxxx`~`0x821a5xxx`**
- p7 内存池：`C-MEMORY` 32 MB（用 50%）+ `U-MEMORY` 8 MB（用 1%，余 8146 KB）
- ⇒ 这些区域**全部远离补丁区 `0x80011504`**（差约 24 MB）

### 3.2 关键地址 / 接口表

| 对象 | 值 | 说明 |
|---|---|---|
| EP 3DLUT 寄存器 | `0x2082B000`…（**`/dev/mem` 读不到**） | ★ 改走驱动或 `st cap path dump ep` |
| LUT 表格式 | `4913 × 4B {R,G,B,pad}`，索引 `((B*17+G)*17+R)*4` | 17 级非格点 `{0,16,…,240,255}` |
| 4 组内置 LUT 缓冲 | `0x810FD100` / `0x81106B00` / `0x81115200` / `0x81101E00` | p7 空间，Linux 读不到 |
| CMA 共享区 | `0x94000000`，144 MB | `/dev/d5_sma`；★ **四点对照的阳性对照点（可读）** |
| ISP 参数块 | 块 A `0x20821300` / 块 B `0x20821700` | 21 槽 × 2 通道 |
| PW 参数模型 | `PW_BASE=0xa3ec`、步长 52/4；14 槽 × 7 维 | 外部直推 id = `0x110/0x111/0x112` |
| **A1 补丁点** | `0x510b0`（重定向）+ `0x11504`（24B 特判块） | file offset = VA − 0x80000000 |
| App 命令表 | `@vaddr 0x449d28`，**32 条** | 8B/项 `{name, handler}`，`0x449e28` 零词止 |
| C-2 补丁点 | `0x3656dc`（`uscom`→`film`）+ `0xc23a8`（桩，**248 B**） | 遗体可用 656 B |
| 队列 key | `0x8828`（SysV） | ★ **f.sh 内禁止向它发消息（自我死锁）** |
| 唯一客观判据 | `st cap iqr`（**184 个 `eIQ_ID_*`**） | "改了生效没有"只信它 |

| # | 死路 | 判据/新证据 |
|---|---|---|
| 1 | 指望 mod_gui 迭代 | 4 控件/2 列/点击即退 |

| 8 | 猜 3D LUT 表格式 | 已解出 |

| 12 | 成片直灌 LUT | E4 实测死路（拍片流程主动重配置档位池） |
| 13 | 自绘全屏 UI | 窗口不显示 + 单核拖死风险 |
| **14** | ★ **`f.sh` 内调用 `st app …`** | ★ **10-12 实验证实**：App 的 shell 线程被 `system(f.sh)` 阻塞期间无法服务同一队列 ⇒ 自我死锁（`W-6`/`SHELL_TO_APP` 附录 A.2） |
| **15** | ★ **把参数原样拼进 `system()`** | ★ **10-12 实测出注入面**：`recipe apply bad;name` 的 `;` 被 `/bin/sh -c` 解释 ⇒ 桩 v2 已加字符白名单净化 |

**硬性操作约束**：
1. `epmc` 单次读 **≤256 regs**（读 1024 会压死相机，实测 3 次）
2. LUT 灌入用 `sel=0`；`sel=2` 会花屏
3. LUT 物理地址 **256 B 对齐**；灌表前必跑 `cmapick2`
4. **不要半按快门**（触发 p7 抢回 LUT 指针；`lutsentinel` 会恢复）
5. 一份 telnet 会话只跑**一条**命令（结果经 FTP 取回，不信回显）
6. 上机批次留散热间隔；★ 10-12 观测：批量 `st cap` 会把 loadavg 抬到 **1.58**
7. 交叉编译一律 **-O0**；相机脚本必须 **LF**

## 9. ★ 10-12 新增纪律与教训（都是当天踩出来的）

| # | 教训 | 影响 |
|---|---|---|
| 1 | ★ **Git Bash 会改写命令行里的绝对路径**：`telnet_run.py '<cmd>'` 中的 `/usr/bin/setsid` 被替换成 `E:/workbuddy/.../setsid` | 上机命令**必须** `MSYS_NO_PATHCONV=1` |
| 2 | ★ **后台任务不可靠**：`run_in_background` 的上机驱动跑完第 1 段后即消失（任务 no found） | **上机驱动一律前台跑** |
| 3 | ★ **`grep` 对含 NUL 的文件默认按二进制处理**：只输出 "Binary file matches" | 数 `eIQ_ID` 时 184 会被数成 1 ⇒ **必须 `grep -a`** |
| 4 | ★ **复合命令（`for` + 块重定向）在 telnet 里不可靠**：一次跑 6 分钟只出 9 字节，且把 loadavg 抬到 1.58 | 改"逐条独立 + 各自重定向到文件" |
| 5 | ★ **中文全角括号 + 嵌套双引号**：`echo "…（UI 只放行"文件版本 > 设备版本"）"` 让 shell 把 `>` 当重定向，凭空生成了个文件 | 中文文本里的引号统一用单引号包裹；改完必 `bash -n` |
| 6 | ★ **相机 ABI 编译的三个坑** | ① 自备 `crt0_arm.S` ② 直链相机 `libc-2.13.so` ③ **`-D_TIME_BITS=32 -D_FILE_OFFSET_BITS=32`**（宿主 glibc 2.39 默认 time64 ⇒ `ioctl` 变 `__ioctl_time64` 链接失败）；④ 缺相机头时从开源包取（已随仓库 `test_server/sysarch/inc/`） |
| 7 | ★ **相机 rootfs 里没有 `timeout`**（根 busybox 也无该 applet）；`busybox timeout` 行为亦不符预期 | 脚本不要依赖 timeout；靠命令自身超时 |
| 8 | ★ **大输出命令一律重定向到文件再 FTP 拉**（`path dump ep` 等） | 避免回显风暴（铁律 88 的"输出量"面） |
