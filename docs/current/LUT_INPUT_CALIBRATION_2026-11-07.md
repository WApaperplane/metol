# 3DLUT 输入曲线标定

日期：2026-11-07
工具：`tools/lutgen/measure_tone.py`（已用合成数据自测：真值 gamma 2.2 → 拟合 2.229）
相机：NX500 1.12（192.168.0.103）

## 为什么拍 JPG 就够，不需要 RAW

3DLUT 挂在 **ISP 末端、JPEG 编码器之前**。它看到的 8bit YCbCr 就是 JPG 里的像素值 —— 均匀色块下 DCT 量化误差 < 1 码。所以：

```
拍 JPG → 测像素码值 = 直接测 3DLUT 的输入端
```

不需要 RAW，不需要知道光源绝对亮度，也不需要辐射度标定。快门比例本身就是精确的 EV 标尺。

## 为什么必须实测

设计 LUT 只有三种起点：

| 做法 | 后果 |
|---|---|
| 凭感觉调（现状） | 单个场景好看，换场景就崩 |
| 假设机内是 sRGB / gamma 2.2 | 如果实际不是 2.2，所有 LUT 全盘偏，且偏得看不出来 |
| 实测本机曲线再反推 | 唯一可靠 |

`sensor + ISP + Picture Wizard` 串起来的实际曲线，没有公开数据，只能测。

## 拍摄协议

### A. 前提（由我执行）

- `lut.sh off` —— **当前 `ACTIVE warm_gold`，不关掉测的就是 LUT 之后的曲线**
- 记录入场状态（LUT 名、WB、光圈、ISO）以便标定后恢复

### B. 布光与靶（需要人做）

| 项 | 要求 |
|---|---|
| 靶 | A4 白纸或 18% 灰卡，**无纹理、无折痕**，平贴墙面 |
| 光 | 均匀：两盏灯 45° 交叉，或阴天窗光。**禁止单灯直射 / 闪光**，会出现热斑 |
| 相机 | 三脚架或稳定支撑，距靶约 0.8 m，靶面填满画面中部（脚本只取中心 34%） |
| 铁律 | 整个序列期间**不动灯、不动相机、不挪位置** |

### C. 相机设置

```
档位      M
光圈      f/5.6          （不要用最大光圈，避免暗角）
ISO       100
白平衡    固定（按光源选区温），不要 AWB
画质      最高 JPG，不拍 RAW
尺寸      最大
驱动      单张
关闭      HDR、SmartRange、LDC、SmartFilter
Picture Wizard   STANDARD
```

### D. 快门序列（16 张，1 EV 步进，约 90 秒）

```
1/4000  1/2000  1/1000  1/500  1/250  1/125  1/60  1/30
1/15    1/8     1/4     1/2    1       2      4     8
```

每张**只改快门**。顺序随意，但中途不能动灯或相机。

偷懒版：如果嫌 16 张多，隔一档拍 8 张（2 EV 步进，1/4000 到 8s），曲线形状仍能看出，只是肩部/趾部定位粗一倍。

### E. 拍完当场自检

- 每张回放：中心应是一片**均匀**灰，看不到阴影、渐变、纸纹
- 最长曝光的 1–2 张应当**全白**（正常，高光裁切点需要它）
- 最短曝光的 1–2 张应当**很暗但不是全黑**
- 若某张中心能看到明暗不均 → 重新布光后整组重拍

## 分析（由我执行）

拍完留在卡上即可，我拉回来跑：

```sh
python tools/lutgen/measure_tone.py <目录>
```

输出四个文件：

| 文件 | 内容 |
|---|---|
| `tone_samples.csv` | 每张：快门、相对 EV、RGB/Y 均值、均匀性、过曝比例 |
| `tone_curve.svg` | 曲线散点 + 线性段拟合线（浏览器直接打开） |
| `tone_lut.csv` | **0–255 码值 → 相对 EV 反查表**，`in_measured_range=0` 为外推值 |
| `tone_report.txt` | 结论摘要 |

报告给出：

- **等效 gamma**：线性段 `log2(Y)` 对 EV 的斜率倒数
- **线性段范围**：曲线真正按幂律走的 EV 区间
- **肩部压缩量**：高光端实测比线性预期低多少码
- **趾部抬升量**：暗端比线性预期高多少码（降噪/黑电平抬升的痕迹）
- **有效动态范围**：可用段跨多少 EV

## 判据

| 实测结果 | 含义 | 对 LUT 设计的影响 |
|---|---|---|
| gamma ≈ 2.2 | 机内接近 sRGB | 可以直接用 sRGB 假设起稿 |
| gamma < 2.0 | 曲线更平、对比度低 | 阴影段码值富余，LUT 可更激进压暗 |
| 肩部早压缩（< +0.3EV 就压 10 码以上） | 高光宽容度小 | 高光区 LUT 不要拉亮，只做色相修正 |
| 趾部抬升明显 | 暗部被降噪抹平 | 暗部色阶已被破坏，LUT 强行提亮会出色块 |

## 后续

拿到 `tone_lut.csv` 之后，才能做真正的「反推式 LUT 设计」：先指定目标曲线（比如某型胶片的 H-D 曲线），再用输入曲线反解出 3DLUT 该给每个输入码值施加的映射，而不是现在这样按感觉调对比度。

## 附：脚本可靠性

用合成数据验证过一遍：构造 gamma 2.2 + 肩部压缩的 15 档序列，脚本拟合出 gamma 2.229、肩部压缩 7.9 码，与解析计算（242.4 vs 实测 242）一致。
