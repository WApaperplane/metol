# 机身 `.cube` 转换器：发布版是旧的，源码版是坏的（2026-10-25）

## 一句话

release 10 包里的 `cube2lut.arm` 是 **RGB 直通**的旧二进制；源码树里那个号称已修成 CrCbY 的版本
**连恒等变换都做不对**（17³ 网格 80% 落在 sRGB 外，被钳掉了）。两个都不能用。本轮重写了边界
处理并重编，实机验证通过，已替换机端两个副本。

## 一、三个版本的实际差别

| 版本 | 大小 / md5 | 恒等 `.cube` 输出 | 对真表 vs 参考实现 |
|---|---|---|---|
| 发布包（release ≤10） | 8,880 B `582b12f0…` | (0,0,0)…(255,255,255) | **max 235，mean 24.5** |
| 源码树旧构建 | 10,504 B `2d94e76f…` | (71,83,80)…(184,173,176) | 恒等都不成立 |
| 本轮修正 | 10,828 B `b798964d…` | (0,0,0)…(255,255,255) | **max 3，mean 0.04** |

参考实现是 `tools/lutgen/native_codec.compile_uniform_rgb`（本轮 30 张外部 LUT 全部由它生成，
并经照片复核）。判据不是"两个二进制彼此一致"，而是"与这个已验证的参考一致"。

发布版的恒等输出看着是对的，所以它一路没被怀疑——但它是把 `.cube` 的 RGB 数值**原样**写成表，
`{Cr,Cb,Y}` 槽照 CrCbY 读，等于把整张图当色度通道解释。它的"恒等正确"只是恒等表恰好对称。

## 二、源码版为什么坏

`crcb_y_to_rgb()` 在 YCbCr→RGB 之后把结果 `clip_q16` 到 [0,1]：

```c
rgb[0] = (unsigned)clip_q16(y + mul_q16(91881, vr));   /* ← 钳死在这里 */
```

`sample()` 又把角落索引和插值权重一起钳在边界。两处叠加的后果：17³ 的 CrCbY 网格有 **80.5%
的格点在 sRGB 外**（release 10 自己测的数），这些点全部被压到边界平面上，恒等变换再也回不来。

复算首项的轨迹可以完全对上（这就是实测的 71/83/80）：
`(cr,cb,y)=(0,0,0)` → 未钳的 RGB 是 (0, 34900, 0) → 钳成 (0, 0.53, 0) → 过恒等立方不变 →
再转回 YCbCr 得 (0.28, 0.33, 0.31) → ×255 = **(71, 83, 80)**。

## 三、改了什么

只动边界语义，色度矩阵系数一个没改：

1. `crcb_y_to_rgb()` 去掉钳位，改成有符号输出，超范围值带进采样。
2. `sample()` 位置参数改有符号 Q16；角落索引钳到 `[0,n-2]` 但**权重保留真实偏移**，
   于是越界点沿最后一格的直线继续延伸（线性外推）。
3. `lerp()` → `lerp_s()`，权重允许 <0 或 >1。

这正是 `native_codec.compile_uniform_rgb(boundary='linear')` 的规则。选它的理由是它**保持仿射
变换精确**——恒等、单色这类线性映射在网格外也必须成立，钳位做不到。

## 四、验证

| 项 | 结果 |
|---|---|
| qemu 跑 `identity17.cube` | 与 `looks/identity17.bin` **逐字节 0 差** |
| **机端实跑** `identity17.cube` | 拉回后与 `looks/identity17.bin` **0 差（19,652 字节全符）** |
| `kodak_gold200` / `fuji_velvia50` / `fuji_classicchrome` | 对参考 max 2–3、mean 0.04，差 >1 的节点仅 3–12/4913（定点舍入） |
| `test_cube2lut.py` | 14/14 通过 |

## 五、别被那几个测试骗了

`test_cube2lut.py` 的 `test_arm_matches_pc_byte_for_byte` 读的是
`raw8/gates/lut/cube2lut_2026-10-18/` 下的**预生成** `*_arm.bin` / `*_pc.bin`，注释也写明了
"ARM 二进制不能在这里跑"。它校验的是 10-18 那天归档的产物互相一致，**不校验当前源码、也不校验
当前二进制**。那批固件是 RGB 时代的，所以修正版装上之后测试照样全过——这是测试的盲区，不是
修正版的免检证明。

真正的验收只有两条：qemu 跑恒等、**机端实跑恒等**。两条都做了。
