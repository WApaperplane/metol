# 2.5K 映射核对（2026-11-07）

> **功能归属**：2.5K 映射是上游 NX-KS 的**原版功能**，不是本项目新增。`resup` 早有 `2K`
> 分支，`res_UHD2K.sh` / `off_res_UHD2K.sh` 也一直在，改的是 `0xe4428` / `0xe442c` 两条立即数。
> 本文只记录本轮对它的**核对、实测与两次自我纠错**。

## 一、原版就有

上游 `scripts/resup` 的 2K 分支（UHD 段）：

```sh
2K) /opt/usr/nx-ks/poker $(pgrep di-camera-app) 0xE4428:5a8ea0e3 0xE442C:0aaca0e3 #2.K#
```

配套两个菜单脚本：

| 脚本 | 行为 |
|---|---|
| `res_UHD2K.sh` | `resup UHD 2K` + 清掉 UHD→DC / UHD→HD 的自动项 |
| `off_res_UHD2K.sh` | `resup UHD UHD` —— **取消勾选时执行，即时回到 UHD** |

判据（`poker` 回读，补齐前导零后比对）：

```text
UHD : 0xe4428 = 878ea0e3 (2160)   0xe442c = 0faca0e3 (3840)
2.5K: 0xe4428 = 5a8ea0e3 (1440)   0xe442c = 0aaca0e3 (2560)
```

## 二、两次纠错（留档，别重犯）

| 原判断 | 实际 | 处理 |
|---|---|---|
| 「取消勾选没有任何恢复动作，必须重启才回 UHD」 | `off_res_UHD2K.sh` 一直在跑 `resup UHD UHD`，取消即恢复 | 判断撤回 |
| 「需要新增按钮，把 2.5K 变成双向、可查询的开关」 | 原 checkbox 本来就是双向的 | 撤去重复按钮；`res_25k.sh` 不接菜单 |

两条都是本轮先写错、后核对推翻。写在这儿是为了下次别再拿"原版没做"当前提。

## 三、本轮真正的增量

| 做了什么 | 性质 | 落点 |
|---|---|---|
| 这个档位到底看到多少画面 | **新数据** | SIFT + RANSAC 单应配准，见 [视频 LUT 与 2.5K 实测](VIDEO_LUT_AND_2K_2026-11-07.md) |
| 菜单文案重排 | **文案** | `gui_res.NX500` 统一成「<档位>档 → <目标>（尺寸）」，不改任何脚本行为 |
| `res_25k.sh` | **诊断工具** | 带 `status`，可直接读两条立即数并判档；确认菜单已有 off 脚本后**不作入口** |

实测（照片与两段视频统一 1600 px 宽做单应配准）：

| 模式 | 照片宽度覆盖 | 照片高度覆盖 | 内点 | 中位重投影误差 |
|---|---:|---:|---:|---:|
| UHD | 59.43% | 50.11% | 304 | 0.292 px |
| 2560×1440 | **98.79%** | 83.34% | 511 | 0.311 px |

「片门全开」只对**视角**成立：这是接近照片全宽的 16:9 视角，不是完整 3:2 open-gate
（上下仍裁）。传感器读出方式、跳行合并、混叠、滚动快门、动态范围均未确认。

## 四、`res_25k.sh` 剩下的用途

```sh
sh /opt/usr/nx-ks/res_25k.sh status   # 读 0xe4428/0xe442c 判断当前档位
sh /opt/usr/nx-ks/res_25k.sh on|off   # 需要绕过菜单直接切时用
```

`poker` 输出会省略高位 0（实测 `0xe43f0:1aaa0e3`），脚本统一 `printf '%08s' | tr ' ' '0'`
补齐后再比对，避免误判成「非标准值」。
