# 2.5K 片门全开开关（2026-11-07）

> 后续核对纠正：原版已有 `resup ... 2K`、`res_UHD2K.sh` **及** `off_res_UHD2K.sh`（调用 `resup UHD UHD`），原菜单取消勾选会执行off脚本。下文“没有恢复动作、必须重启”的判断不成立。根据用户要求，已撤去重复按钮，统一使用“实用功能 → 分辨率修改”的原有checkbox；保留本文件和res_25k.sh作为历史记录，不再由菜单调用。

> 承接 [视频 LUT 与 2.5K 实测](VIDEO_LUT_AND_2K_2026-11-07.md)。本文只解决一件事：**把 2.5K 从「一次性脚本」变成可双向、可查询、不需重启的开关**。

## 问题

既有 `gui_res.NX500` 里已有 `checkbox|UHD映射为2.5K|res_UHD2K.sh`，但该脚本只做「开」：

```sh
/opt/usr/nx-ks/resup UHD 2K
rm -f /opt/usr/nx-ks/auto/res_UHDDC.sh
```

取消勾选时没有任何恢复动作，`0xe4428/0xe442c` 仍是 2560×1440 的立即数，**必须重启才回到 UHD**。

## 实现

新增 `scripts/res_25k.sh`：

| 子命令 | 行为 |
|---|---|
| `status` | 读 `0xe4428/0xe442c` 判断当前档位，输出「2.5K 开 (2560x1440)」/「2.5K 关 (UHD 3840x2160)」/非标准值 |
| `on` | `resup UHD 2K` + 补 `auto/res_UHD2K.sh`（持久化） |
| `off` | `resup UHD UHD` + 删 `auto/res_UHD2K.sh`，**立刻恢复 UHD** |
| 无参数 | 按当前状态切换 |

判据（`poker` 回读，补齐前导零后比对）：

```text
UHD : 0xe4428 = 878ea0e3 (2160)   0xe442c = 0faca0e3 (3840)
2.5K: 0xe4428 = 5a8ea0e3 (1440)   0xe442c = 0aaca0e3 (2560)
```

`poker` 输出会省略高位 0（实测 `0xe43f0:1aaa0e3`），脚本统一 `printf '%08s' | tr ' ' '0'` 补齐后再比对，避免误判为「非标准值」。

弹窗反馈用 `popup_timeout`，开/关各一句，无需再进菜单确认。

## 菜单入口

`gui_res.NX500` 首行插入：

```text
button|2.5K 片门全开 开/关|res_25k.sh
```

保留原 checkbox 不动。两者状态天然同步：`res_25k.sh on` 补的就是同一个 `auto/res_UHD2K.sh`，所以勾选框会跟着变；checkbox 语义是「`auto/` 里有同名脚本即选中」（FEATURE_MATRIX G02），因此不会打架。

## 部署校验

本地 `scripts/`、SD 母本 `/mnt/mmc/scripts/`、机身 `/opt/usr/nx-ks/` 三处 MD5 一致：

| 文件 | MD5 |
|---|---|
| `res_25k.sh` | `f13deb28f5ac0f19496e2928b9f7b051` |
| `gui_res.NX500` | `a22b4ee34625c7ae00f3c8df87cadcfe` |

## 实测

```
=== off    → OK off；status: 2.5K 关 (UHD 3840x2160)；auto/res_UHD2K.sh 消失
=== on     → OK on ；status: 2.5K 开 (2560x1440)；auto/res_UHD2K.sh 恢复
```

冷启动沿用既有 `auto/res_UHD2K.sh` 路径，时序已由 0326 实录（2560×1440 HEVC）验证。
