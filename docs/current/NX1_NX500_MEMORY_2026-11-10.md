# NX1 与 NX500 内存对比（2026-11-10）

用途：给"录像态每帧多出约 9 ms"这条主线提供硬件底账。数据来源全部标注，含实测／静态／推断三级。

## 一、结论

| 维度 | NX1 | NX500 | 比值 |
|---|---:|---:|---:|
| 平台内存池（图像子系统可见） | **1696 MB** | **704 MB** | **2.41×** |
| 池的物理区间 | `0x96000000 – 0x100000000` | `0x94000000 – 0xC0000000` | — |
| 其中空闲可分配 | 1140.97 MB（连拍中实测） | 501.11 MB（闲置实测） | 2.28× |
| 已用 | 555.03 MB | 202.89 MB | 2.74× |
| Linux 可见 | 512 MB（524288 KB） | 512 MB（524288 KB） | 1× |
| Linux 可用／保留 | 115000k / 409288k | 142828k / 381460k | — |
| CMA 保留块 | 256+288+128+72 = **744 MiB** | 288+128+72 = **488 MiB** | 1.52× |
| DDR 时钟 | **800 MHz**（MV_UD 请求值，非实机读数） | **700 MHz**（`drime5-ddrfreq/ch_a` 实测） | 1.14× |
| DDR 通道初始化 | **读 A、B 两路** | **只读 A 路** | 关键差异 |
| SoC 分档 | ASV **6** / IDS 26,38 / PROMISE 87 | ASV **5** / IDS 23,35 / PROMISE 82 | 同代低一档 |
| VDD_ISP | 770 ←1400 mV @ **1030 mV** | 770 ←1400 mV @ **870 mV** | NX500 电压更低 |

一句话：**NX1 是 2 GB 里给图像 1696 MB、双通道 800 MHz；NX500 是 1 GB 里给图像 704 MB、单通道 700 MHz、同代 SoC 的低一档 bin。**
不是"软件阉割"，是同一代 die 的两个 bin + 少焊一颗 DRAM。

## 二、`st cap capmm show` 原始数据

NX500（clean，源自社区文档 `1RONMAN/nx500_nx1_modding/doc/NX1_NX500_hw_differences.md`）：

```text
- Total Memory          : 738197504 bytes (704.00 MB)
- Cur/Max Allocable     : 525451264 bytes (501.11 MB)
    . Cache Memory      :  94699520 bytes ( 90.31 MB)
    . NonCache Memory   : 430751744 bytes (410.80 MB)
- Used Memory           : 212746240 bytes (202.89 MB)
```

NX1（连拍中取，故 allocable 偏低，不能与 NX500 闲置值直接比）：

```text
- Total Memory          : 1778384896 bytes (1696.00 MB)
- Cur Allocable         : 1196392448 bytes (1140.97 MB)
- Max Allocable         :  863404032 bytes ( 823.41 MB)
- Used Memory           :  581992448 bytes ( 555.03 MB)   ← 其中含 M/S 已占的 JPEG 区
```

内存图语义：`P`=PP / `I`=IPC / `C`=Common / `M`=JPEG Main / `S`=JPEG Screen / `R`=SRW / `O`=A9。

- NX500 闲置时 `I`（IPC）占 `0x94000000` 起前 4 行 × 28 MB ≈ **112 MB**，之后一路 `.`（空）到
  `0xBA800000`，`C`（Common）从 `0xBA800000` 到池尾 ≈ **88 MB**。**没有 M/S/R 区**（未分配）。
- NX1 连拍时 `I` ≈ 112 MB，`M` 从 `0x9D000000` 起、`P` 从 `0xB7400000`，状态不同不可逐格比。
- 结论只取"池大小"这一项，逐格对比无意义。

## 三、带宽算术（推断，非实测）

LPDDR3 口径：`MT/s = 时钟 × 2`，单次 4 B/32-bit lane。

| 假设 | 带宽 |
|---|---:|
| NX500 32-bit @700 MHz（1400 MT/s） | 5.6 GB/s |
| NX500 若 64-bit @700 MHz | 11.2 GB/s |
| NX1 64-bit @800 MHz（1600 MT/s） | 12.8 GB/s |

全宽 4K 输入按对方交接的窗口算：`stride 9920 × 3680` ≈ **36.5 MB/帧**，29.97 fps 仅"读一遍"就
≈ **1.12 GB/s**；全链（BayerStill→LDC→EP→HEVC，每级至少读+写）按 3–5 倍全分辨率帧估
≈ **3.0–5.2 GB/s**。

⇒ 在单通道 5.6 GB/s 下是 55–93% 占用，在 12.8 GB/s 下只有 23–41%。
**这条算术能解释"录像态多出的 9 ms"，但成立与否取决于两个未测项：实际总线位宽、各级是否走 DDR。**
不能把它当已证结论——与对方 R10i 的纪律一致。

## 四、可证伪的三步

1. **位宽**：`/sys/devices/platform/drime5-ddrfreq/ch_a` 只给频率与分频，不给位宽；位宽要从
   DDR 控制器初始化（p7 侧或 `board-d5_*.c`）读 `DDR_MR`／`CTL` 配置字，或看 PCB 上 DRAM 颗粒位数。
2. **通道数**：NX1 init 读 A/B 两路、NX500 只读 A —— 这是明确代码差异，但是否等于少一颗颗粒，
   需要 `st cap capmm show` 之外的物理证据（器件丝印／PCB 照片）。
3. **各级走不走 DDR**：把 IPC/EP 每级的 DMA 源/目的地址与窗口对齐，和 `0xB…` 段映射对一下，
   就能确定是不是 3–5 次全帧搬运。R10i 已有 136 个 DMA 字段快照，可复用。

## 五、对我们的直接影响

- 他的 SRW 工作区 **192 MiB**：NX500 闲置可分配 501 MB，放得下，但同时开 SRW + 3DLUT + 取景
  余量只剩约 300 MB。这是"机内显影能不能与视频 LUT 共存"的硬约束，不是风格问题。
- 我们做 **3DLUT + 视频 LUT 监视** 时额外占用极小（19,712 B/张，槽在 p7 空间），不受影响。
- 全宽 4K 若真要稳定 30p，瓶颈优先级应是**减少搬运级数**，而不是提频（对方已算过：即使按
  700→800 线性缩放也只到约 37 ms，仍超 33.37 ms 预算）。
