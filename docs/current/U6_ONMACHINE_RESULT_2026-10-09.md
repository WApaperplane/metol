[2] cmasafe 真机校准：rc=0 四查全绿
[3] pick：0x8f800000（后续漂移 0x8f805000 → a000 → f000 → 0x8f814000，均 +0x5000 自洽）

[4]   identity 写 0x8f800000 → 用户："明显偏色"（色调未定）→ 触屏对焦恢复（LUT0→0x81115200）
[5']  std 写 0x8f805000     → 用户："暗紫红+亮青绿"（与 preview 方向一致）★观察含引导偏差
[5''] fileid#1 写 0x8f80a000 → **画面不变** → 对焦恢复（LUT0→0x81115200）
[5''] fileid#2 写 0x8f80f000 → 用户："变了"（颜色方向未指明）  ★ 规律发现点

## 2. ★★ 规律：写表生效条件 = 前置"抢回态"

### 2.1 A/B 对照（唯一变量 = 写前 LUT0）

| # | 表 | 写前 LUT0 | 画面结果 |
|---|---|---|---|
| 1 | identity | 0x81115200（p7 态） | 变化 ✓ |
| 2 | std | 0x81115200（第 1 次对焦后） | 变化 ✓ |
| 3 | fileid | **0x8f805000（上次地址）** | **不变 ✗** |
| 4 | fileid（重写） | 0x81115200（第 2 次对焦后） | 变化 ✓ |
| 5 | portra | 0x81115200（第 3 次对焦后） | 变化 ✓ |

**表 3 vs 表 4：同表、同流程、同落点模式，唯一差别 = 写前是否处于 p7 态 ⇒ 因果成立。**

### 2.2 机制候选（待 E 系列实验分辨）

- **H1**：DMA/内部状态机在"非 p7 态"拒绝新加载；p7 抢回（重灌）时复位。
- **H2**：官方 API `op_init` 对"已配置过的状态"静默跳过（bypass 语义），导致新 load 不配置通道。
- **H3**：`intr_wait` 超时未清（RD_FINISH 标志悬挂）→ 后续 DMA 请求被挡。
- 旁证：三次"抢回态" regdump 逐字节相同（§4.1）——p7 抢回把整个子系统置于确定状态。

### 2.3 对使用法的影响（先行结论）

- **换表操作流 = "对焦一次（触发抢回）→ 写表"**；
- **拍摄行为（对焦/快门）会触发抢回 ⇒ 表在快门时刻的存活问题（P7_RECLAIM_COUNTERMEASURE 的实证增强：抢回是"必然且频繁"的）**；
- lutpick `--ch1`（LUT1 双通道）+ lutsentinel 守护的价值上升（E1 前提不变）。

## 3. ★★ 判据重构：identity ≠ 中性

### 3.1 离线证据（逐字节 + 渲染）

| 表 | 旧名 | 实际 |
|---|---|---|
| `0x80897BC0` | "identity" | **低对比灰调表**：白点→(185,185,255)；4092/4913 项非恒等 |
| `0x80892EC0` | "标准" | **强风格**：暗部品红/紫、亮部黄绿青（交叉调） |
| 我们生成 identity | — | 4913/4913 严格恒等（生成链无误） |

### 3.2 推论链

1. 相机平时画面 = 出厂表（当前 LUT0=0x81115200）**处理过**的画面；"未灌表/正常"≠"无 LUT"；
2. 写 identity = **移除风格处理** ⇒ 画面必然变化（且变化 = "偏色的反向描述"）；
3. ⇒ 旧判据（写 identity 应中性）**作废**；
4. ⇒ **新判据**：写不同表 → 画面呈现**可分辨的、与表语义一致的（离线可预测的）不同效果**。

### 3.3 遗留矛盾

- portra "整体偏红 + 中性色也偏" vs 表 diag 中性保持 —— **待拍屏客观化复核**（流程：重写 portra → 手机拍屏 → 对话图像分析）。

## 4. 硬件取证

### 4.1 "抢回基准态"（重要指纹）

`regdump_after`（identity 抢回后）/ `regdump_t4`（fileid#1 后抢回态）/ `regdump_t5`（fileid#2 前）
**三份 5.5KB dump 逐字节相同（md5 `922710fffa860128ebb7cc775e6e15b4`）** ⇒ p7 干净态的确定性指纹。

### 4.2 生效态对比（t3=fileid vs t6=portra）

- 全量 80KB dump，**仅 34 行差异（17 对），全部为"LUT0 地址同步"**；
- 精确计数（10-10 离线复核）：**16 个物理寄存器**（`+0x00c` + `k×0x100`，k=0..15）全部跟随 LUT0 值
  （dump 显示"17 处" = 上述 16 个 + header 复显 1 次）；
- 其余寄存器（0x014+ 区域的 0x10 序列 / 0x13020619 常量）**两态间完全相同**。

### 4.3 ★ "0x014+ 两态之谜" —— 10-10 离线分析结论（P4）

**现象定量**（parse regdump_t3 / t6 / final）：
- 生效态（t3/t6）：**1008 个非零项 = 16 单元 ×（5 头部项 + 58 个 `0x00000010`〔+0x014..+0x0f8〕）**
- 抢回态（final 及 after/t4/t5 同型）：**80 个非零项 = 16 单元 × 5 头部项**；+0x014.. 全零

**三个硬事实**：
1. +0x014..+0x0f8 = **58 × u32=0x10**，**16 单元完全一致**（含头部与戳）；
2. t3（fileid）与 t6（portra）该区**逐字节相同** ⇒ **与表内容无关**（"影子区曝光表数据"候选解释**排除**）；
3. 只在"装载过表"后出现、抢回后清零 ⇒ **是"装载动作"留下的状态**。

**可证伪主假设 H-P4a**：该区 = **装载配置模板/描述符残留**（装载时填 0x10、op_init 清零）。
**验证法**：加载任一新表后 dump——仍为 58×0x10 ⇒ 支持；内容随表/参数变化 ⇒ 转 H-P4b（描述符残留，与装载参数相关）。

**16 单元结构模型**：`0x2082b000` 窗口 = **16 个同构 LUT 单元**（每 0x100B）；地址寄存器 LUT0/LUT1（@+0x0c/+0x10）与"装载区"在 **16 处镜像**
⇒ **"写 LUT0 地址 = 广播到全部 16 单元"**（单点写全局生效的架构解释）。

**实操推论**：① 0x014+ 非零 = "曾装载"旁证判据；② **不能**用于反推表内容；③ 抢回 = 全单元同步复位（与 LUT1 守护设计相容）。

**★ 10-11 离线深化（P4 结案）**：四层证据链（p7 全镜像逐字节扫描 / Linux 侧 6 二进制 / libudd5.so 通路解密 /
chunk-02 内核设备资源表）已穷举全部软件写面 —— **该窗口只被写 5 个寄存器 `{+0,+4,+8,+c,+10}`**；
`+0x014+` 与 16 镜像**无任何软件写入路径** ⇒ 定性为**3DLUT 硬件块内部状态区**（装载 pulse 后自填充、复位后自清零）；
**窗口 = 4KB（16 单元 × 256B）经内核资源表权威确认**（`0x2082b000–0x2082bfff`）。
详见 `P4_HW_WINDOW_CONFIRMED_2026-10-11.md`（含证伪条件与方法论备忘）。

### 4.4 save 通道

## 5. 根因分析（10-09 夜追加）：为什么"写表后画面偏色"

**质疑（用户）**："几次写入（含机身自带表）都出现偏色 ⇒ 是否相机自身链路有问题？"

**结论：现有证据不支持"链路系统性故障"；"偏色"的主因是"换表必变" + "主观基准"，最终闭环见 runbook 附录 C。**

### 5.1 三层解释

| 层 | 内容 |
|---|---|
| L1 客观必然 | 平时画面 = 出厂档（`0x81115200`）表处理后的画面；写**任何别的表** ⇒ 画面必变。"偏色"首先是与"平时基准"的差值描述，不等于故障 |
| L2 观察偏差 | 取景器小屏 + 记忆对比 + 无客观图像 ⇒ 描述易被放大/漂移（"偏黄/暖"表述被撤回即一例） |
| L3 可能的真异常 | ① 非抢回态写入不生效（已发现、已规避）② `intr_wait` 超时（历史常态，DMA 完整性未闭环）③ `fmt=1`/表为 RGB 的参数组合未复核 |

### 5.2 支持"链路忠实"的旁证（4 条）

1. std 表写入 → "暗紫红+亮青绿"，与离线 preview 方向一致（★ 含提问引导，待复核）
2. fileid 表 A/B（不生效 vs 生效）：**画面行为完全随写前状态变化** ⇒ 写入链可控
3. portra 写后"整体偏红" ↔ 表体检测 R 增益峰值 1.29 + G 暗部压制（**方向自洽**）
4. 四张表四种可辨效果（identity/std/fileid/portra 各不相同）——"固定系统偏色"会**抹平**这种分辨力

### 5.3 缺的一环（决定性实验）

"写平时表 → 平时画面"从未验证（`0x81115200` 字节读不到）。**已定位文件版候选**：
4 静态档家族（STD×4 + ID×4，同族微调）；档1 = STD#0 已证；**档4 候选 = ID#1/#2/#3**
（`0x8aafc0` / `0x8afcc0` / `0x8b49c0`，slot 版已推相机 /mnt/mmc/u6/）。
⇒ 实验 = **runbook 附录 C**（拍屏基准 + 逐候选匹配）。
判据：候选画面 == 平时画面 ⇒ 链路完全忠实、"链路故障"假设排除；全候选皆不匹配 ⇒ 才需深挖（DMA 完整性 / fmt）。
