## 3. QEMU 可验证性矩阵（本轮实测边界）

| 类别 | 能否离线验 | 本轮实证 |
|---|---|---|
| **字体 / 中文渲染** | ✅ | `SDIC_GP_US` 49,864 字形，CJK 真轮廓；**本轮已出图 10 页，零 tofu**（`raw8/repro/ui_page_p*.png`） |
| **EFL 栈齐备 + evas buffer 引擎** | ✅ | 5 库全在位；`buffer` 引擎可渲染到内存，**无需 X / 无需相机** |
| **配方引擎端到端** | ✅ | guest 产物 md5 == PC 侧，**逐字节相同**（S5） |
| **脚本语法 / CRLF / 执行位** | ✅ | `check_scripts.py` 已 CI 化 |
| **UI 布局 / 信息结构** | ✅ | 本轮 10 页出图（降级绘制：rect + text） |
| **真实 elm 控件外观** | ❌ | `elm_init` 在无显示服务的 chroot 里会挂死 ⇒ 只能"降级绘制" |
| **寄存器 / EP / IPC** | ❌ | QEMU `-M virt` 没有 `0x2082b000` 这些物理地址 |
| **按键 / 波轮 keysym** | ❌ | 需真实键盘矩阵 + 内核 input 驱动 |
| **ISP 是否消费参数** | ❌ | 只有 `iqr` / `check` 在真机上能答 |
| **相机内核能否在 QEMU 起** | ❌ **本轮实测否定** | 相机内核 = Samsung 3.5 BSP、非 DT：`-M virt` **零 console 输出**、`-M vexpress-a15` 立即 reset 退出（证据 `raw8/repro/qemu_vm_boot.log`） |

### 3.1 ★ 本轮用到的两条 QEMU 通道（分工写清，别混）

| 通道 | 命令/脚本 | 用途 | 本轮结果 |
|---|---|---|---|
| **用户态模拟**（主通道） | `qemu-arm-static` + `chroot`；`test_server/filmlab/src/run_modui_chroot.sh` | 跑相机用户态（出图 / 跑 ARM 程序） | ✅ **10 页 UI 出图成功**（G3 证据恢复） |
| **系统模式**（真虚拟机） | `qemu-system-arm -M virt`；`test_server/filmlab/src/qemu_vm_run.sh` | 起真 ARM 虚拟机，**相机 rootfs 作为 VM 的根**，guest 内**原生**执行 | ✅ **10 页 rc=0**（`raw8/repro/qemu_vm_run.log`） |

### 3.2 ★ 系统模式的三条路取舍（本轮实测，别重复踩）

| 路 | 组合 | 结果 |
|---|---|---|
| ① | 相机自己的内核 + `-M virt` / `-M vexpress-a15` | ❌ **零 console 输出**（Samsung 3.5 BSP、非 DT）——证据 `raw8/repro/qemu_vm_boot.log` |
| ② | 通用内核 + rootfs 作 virtio 磁盘 | ❌ Alpine lts 内核 `VIRTIO_BLK`/`VIRTIO_MMIO`/`EXT4_FS` **全 `=m`**，initramfs 无模块 ⇒ `mount /dev/vda` = **No such device** |
| ③ | 通用内核 + **rootfs 打进 initramfs** | ✅ **采用**：内核自带 initramfs 装载，不依赖块设备驱动 |

⇒ ★ 结论：**"用 QEMU 虚拟机跑 mod 用户态"是可行的**，但必须用通用 armhf 内核（相机内核不可用于通用机器模型），
且走 initramfs 而非磁盘挂载。
