# LUT 滤镜 UI 端口（2026-10-18）

> **一句话**：LUT 换表做成了 NXUI 的第三个模式，绑在 **EV+WiFi** 上，主菜单也有入口。与 filmlab 完全独立，可叠加。退出 UI 自动还原。

## 0. 入口

| 入口 | 路径 | 说明 |
|---|---|---|
| **EV+WiFi** | `scripts/EV_MOBILE.sh`（→ `/opt/usr/nx-ks/EV_MOBILE.sh`，keyscan 槽位） | 启动 LUT UI（`nxui.sh lut`）；**不再起 telnet/FTP** —— 该职能已由主菜单 `IP: x.x.x.x [Telnet关]` 的 `telnet_toggle.sh` 接管。NXUI 未启用时只弹提示 |
| **主菜单 → 实用功能** | `gui_func.NX500` 新增 `button|LUT 滤镜|nxui.sh lut` | 静态菜单项 |
| 命令行 | `nxui.sh lut` | 等同 EV+WiFi 的 UI 部分 |

**为什么不新开一个独立可执行文件**：`menu.sh` / `EV_EV.sh` / `EV_AEL.sh` 三个入口已经全部转发 `nxui.sh`，再抢按键必然冲突。因此复用同一进程，只是换数据源和执行器。

## 1. 与 filmlab 的关系：不冲突，可叠加

| 层面 | filmlab | LUT |
|---|---|---|
| 数据通路 | `prefman`/`setusr` → PW 7 维标量 → p7 档位池 `0xdc..0xe2` | 3D LUT 表（A18 槽）+ 登记表 |
| 存储 | pref 分区 4 个 CUSTOM 槽 | p7 内存池 |
| 触发 | `seq 0x13B` | 半按 / PW 触发连带重载 |
| UI 模式 | `nxui.sh filmlab`（默认） | `nxui.sh lut` |

两者作用在不同层，**同时生效等于双重调色**——这是设计选择，不是 bug。UI 上以标题区分（`LUT / 3D 滤镜` vs `FILMLAB / 滤镜预览`）。

## 2. 三个安全设计

| 设计 | 实现 | 理由 |
|---|---|---|
| **半按不还原** | 半按只 `XUnmapWindow` 隐藏面板，不走退出路径 | 半按是为了让开画面拍照；若此时还原，照片就丢掉 LUT |
| **退出必还原** | `main()` 末尾 fork+exec `lut.sh off` | 相机不会被留在"表被改写"的状态 |
| **dry-run 只读** | `lut_mode && !live` 时 action 用 `status` 而非 `apply` | `apply` 是真写入，dry-run 不能碰 |

`off` 还原三样：`View4[3]` → A17、`Still6[6]` → 原厂、A18 槽 → 备份内容。备份在**首次写入前**由 `lut.sh begin`/`apply` 自动生成，后续 `apply` 用 `still-write`/`write` 模式**不覆盖**首次备份。

## 2.5 实测反馈修复（10:57）

首次上机后用户反馈"最初几次切换很快，多试几次就失效"。根因是两个 bug 叠加：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `apply` 只写表 + 改登记表，**不触发 p7 重载** | 点按后画面不变，必须等半按 |
| 2 | **半按 = 关闭 UI**（`event0` code 125 → `close_requested` → `break` 退出），退出走 `lut.sh off` | 用户"点几下再半按"时，最后一次写入被还原 |

修复：

| 项 | 实现 | 验证 |
|---|---|---|
| `nx_regtabwrite.arm reload <addr>` | 照 p7 在 `0x804A5C44` 的写序：`OnOff→Pulse清→Pulse bit0→LUTA←addr→Cfg原值→Pulse\|bit8→Pulse清`，读回 `load_addr` 与 `Cfg` 双验证 | 上机 `RELOAD ok`，`load_addr` 立即变 `0x81119f00` |
| `lut.sh apply` 末尾调 reload | 成功打 `OK applied`，失败打 `WARN ... half-press once` | 连续 `warm33→identity17→neg` 三次均 `RELOAD ok` |
| `lut.sh off` 末尾 reload 回 A17 | 登记表回原厂**不够**——硬件 SRAM 里仍是上一张表 | `off` 后 `load_addr=0x81115200` |
| `nxui.c` 半按判断加 `&& !lut_mode` | LUT 模式下半按不再关闭/还原 | 代码级，待实测 |

**`off` 那条是最容易漏的**：只改登记表的话，硬件里仍是最后一张表，画面停在负片，看起来像"关不掉"。

## 7. ★ 面板"配方表不可用"事故与修复（2026-10-18 12:1x）

### 7.1 现象

往 `looks/` 铺了 25 个 look 后，LUT 面板不显示任何条目，只有一句
"配方表不可用 · 请先导出配方"。同一句在配方模式和 LUT 模式共用，
所以看不出到底哪一边出错。

### 7.2 定位

用 `--dry-run` 直接读加载器，绕开面板：

```sh
B=/opt/usr/nx-ks/nxui/nxui.arm
DISPLAY=:0 $B --root /opt/usr/nx-ks --recipes /mnt/mmc/filmlab/recipes.txt \
    --engine /opt/usr/nx-ks/filmlab.sh --dry-run --lifetime-ms 400
# READY ... recipes=68      ← 配方模式正常

DISPLAY=:0 $B --root /opt/usr/nx-ks --recipes /mnt/mmc/lut/list.rec \
    --engine /opt/usr/nx-ks/lut.sh --lut --dry-run --lifetime-ms 400
# READY ... recipes=0       ← LUT 模式空
```

`list.rec` 里有 25 行，格式也对。差别在**名字**：

```
samsung_A00|samsung_A00|0|0|0|0|0|0|0     ← 含大写
```

### 7.3 根因（两层）

**第一层：`nx_key_valid()` 只允许 `a-z 0-9 _`。**
`A` 不在集合内 ⇒ 该行被拒。

**第二层（致命）：`nx_load_recipes()` 是整表作废语义。**
任一非法行 ⇒ `goto bad` ⇒ 返回 -1 ⇒ `count=0` ⇒ 面板显示"配方表不可用"。
**三个大写文件名，让 25 个 look 全部消失。**

⇒ 面板容量、`list.rec` 格式、`lut.sh list` 输出、`awk` 可用性、`recipes.txt`
（68 行全部合法）都逐一排除过，问题只在 key 字符集。

### 7.4 为什么改不了文件名

`/mnt/mmc/looks` 在 exFAT 上，**大小写不敏感**：

```
mv: 'samsung_A00.bin' and 'samsung_a00.bin' are the same file
```

⇒ 靠改名规避这个 bug 行不通。必须改校验。

### 7.5 修复

| 文件 | 改动 |
|---|---|
| `nxui_model.c` | `nx_key_valid()` 只拒绝结构性非法：`\|`、控制字符、空串、超长；**大写 / `-` / `.` / UTF-8 全部放行** |
| `nxui_model.c` | 所有拒绝路径改为 `RECIPE_BAD()` 宏，**打印 `文件:行号: 原因`** 到 stderr（如 `bad key 'x'`、`field 4 = 300 out of range 0..200`、`expected 9 fields, got 8`） |
| `nxui.c` | 空表文案按模式分叉：LUT 模式 → "滤镜库为空 · 见 /tmp/nxui.log 与 /mnt/mmc/looks"；配方模式 → "配方表不可用 · 见 /tmp/nxui.log" |

保留整表作废语义：宁可全空也不半解析，避免用残缺列表驱动相机。

|---|---:|---:|
| LUT 模式 `recipes=` | **0** | **25** |
| 配方模式 `recipes=` | 68 | 68 |
| `list.rec` 大写残留 | 3 行 | 0 行 |

## 8. 严重品红/绿偏色的根因：不是 bug，是选表（2026-10-18 12:2x）

### 8.1 结论先行

用户实测后报告"几个配方出现非常严重的品红或绿色偏色"。逐一排除后，
**转换链路没有错**，是那些表**本身就是极端风格**：它们在中性灰上就带有
50–180 级的通道落差，灌进取景器自然整片偏色。

### 8.2 排除的三个方向

| 假设 | 检验 | 结果 |
|---|---|---|
| 轴序错位（R/G/B 轴被置换） | 灰点附近求 3×3 响应矩阵，看是否退化成置换阵 | **18 张全部对角占优**，无置换 |
| 转换器把 13³ 转错 | 4 张与 PC 浮点参考逐字节比（maxdelta ≤ 1 LSB） | 一致 |
| 极端色格点被截断 | 统计 0/255 占比 | 仅 velvia50 达 2.7%，其余 < 1% |

⇒ 三者都不成立。剩下的解释只有"表的设计本身"。

### 8.3 量化指标：灰轴最大落差

**定义**：输入中性灰 (v,v,v) 时，输出 `max(R,G,B) − min(R,G,B)` 的最大值（8bit 级）。
这是肉眼能直接看到的整体偏色幅度，与场景内容无关。

| 分级 | 落差 | 含义 |
|---|---:|---|
| safe | ≤ 12 | 正常胶片染色，肉眼视为"白平衡正常" |
| mild | 13–25 | 轻微色调，可用 |
| strong | 26–50 | 风格强烈，需配合题材 |
| extreme | > 50 | 整片偏色，日常不可用 |
