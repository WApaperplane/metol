# P7 抢回表指针 —— 处理方案（2026-10-09）

> ⚠️ **2026-10-18 文档清理：本文结论已被取代。** 本文的 R-B 路线（表进 LUT1 + `lutsentinel` 守护）**已退役**：需抢时序、只覆盖预览、不抗抢回。现行路线是 LUT0 登记表重定向。
> 现行结论见 [`LUT_RETARGET_LIVE_2026-10-18.md`](LUT_RETARGET_LIVE_2026-10-18.md)。


> 问题（LUT 链路 v2 核心）：直灌硬件 LUT0 的表，会在 p7 的表重载事件（半按对焦 / 切档 /
> 拍片）后被**抢回**——画面回到出厂表。本文给出**系统性处理方案**：
> 双通道隔离（表放 LUT1）+ 寄存器级守护恢复 + 拍片流程 + 实验矩阵。
> 依据：`3DLUT_APPLY_PATHS`（QEMU 写序）· `3DLUT_VIEW_STILL_ISOLATION` · QEMU S4/S8 场景数据。
> 产物：`lutsentinel.arm`（新守护，已编译）+ `lutpick.sh --ch1/sentinel`（已集成）。

---

## 0. 一句话

> **p7 每次重载只碰 LUT0 通道**（写它的表地址 + 把 `Cfg.SelLUT` 写回 0）。
> ⇒ 我们的表改放 **LUT1**（`sel=1` 装载）；被抢回后**只需把 `Cfg.SelLUT` 写回 1**
> （一个寄存器写、微秒级、无 DMA）——`lutsentinel` 守护自动完成。
> "当前这张照片"若在抢回瞬间曝光，仍受 p7 支配（除写档位池，见 §3-L3）。

---

## 1. 机制（为什么被抢回 —— 全部有 QEMU/静态证据）

p7 的表重载是**事件驱动**（非每帧），事件经唯一写表函数 `FUN_004a5e30`，写序（QEMU S4 实测）：

```
[0x2082b000] <- 0x1        OnOff=1
[0x2082b008] <- 0x0/0x1    Acc 使能
[0x2082b00c] <- <p7的表地址>  ★ Load 目标地址（它自己的表）
[0x2082b004] <- <SelCbCr>   Cfg：清除/设置 SelCbCr
[0x2082b004] <- <SelLUT>    ★ Cfg：SelLUT 写回它的 sel（=0）
[0x2082b008] <- 0x101/0x1    Load 启动脉冲（先置后清）
```

两个后果：① 硬件 **LUT0 单元 SRAM** 被 p7 的表 DMA 覆盖；② **`Cfg.SelLUT` 被写回 0**
（硬件切回 LUT0 通道）。我们的处理必须针对这两点分别出招。

**路径证据**：
- View::_load 提交 = `FUN_00179314(iVar5, 0, fmt, 0)` —— 第 2 参（sel）**= 0**（API_GUIDE 摘录）
- MCB 线：`FUN_004a5c44(table, 0, 0, 0)` —— sel=0（QEMU S8）
- ⇒ **p7 全家都用 sel=0（LUT0）**；LUT1 单元是"它不碰的邻居"。

---

## 2. 关键洞察：双通道隔离 + 寄存器级恢复

**硬件事实**（QEMU 逐条实测）：

| 事实 | 证据 |
|---|---|
| Cfg `bits[5:4]` = **SelLUT**（0/1/2） | S4：sel=1 → Cfg 终态含 `0x10`；sel=2 → `0x20` |
| `sel=1` 装载 = 表进 **LUT1**，Cfg 指向 LUT1 | S4 sel=1 写序：`+0x00c ← 表地址` + `Cfg ← 0x10` |
| `setPWColor` 时代历史结论"sel=2 花屏、sel=0 正常" | lutapi_help.sh（**sel=1 从未被实测** ⇒ E1 实验第一问） |
| p7 抢回 = 只写 LUT0 + SelLUT→0 | §1 写序 |

⇒ **方案**：
1. 用 `lutapi load <表> <phys> 1 1 17 2 300 0`（**sel=1**）把表装进 LUT1；
2. p7 抢回后：LUT1 的表**原封不动**，只需把 Cfg.SelLUT 改回 1；
3. 恢复动作 = 官方 `d5_ep_3dlut_op_init(sel=1, fmt=1, cbcr=0, bypass=0)`
   —— 反汇编证明它只写 Cfg（OnOff/Acc/SelCbCr/SelLUT/格式位），**不碰表地址、不触发 DMA**。

**收益对比**：

| 方案 | 恢复动作 | 耗时/风险 |
|---|---|---|
| 重灌守护（旧思路） | 20KB DMA 重灌 + 落点复检 | 秒级；撞 p7 活动期风险 |
| **本方案（双通道）** | **1 个 32-bit 寄存器写（op_init）** | **微秒级；零 DMA** |

## 3. 四层防御（按依赖排布）

| 层 | 内容 | 状态 |
|---|---|---|
| **L0 操作纪律** | 不半按直接拍；画面回退时 `lutpick apply` 重灌 | 立即可用（零工具） |
| **L1 lutsentinel 守护** | 轮询 Cfg.SelLUT；被写回 0 → op_init 恢复为 1 + 日志 | ★ 本方案核心（工具已就绪） |
| **L2 拍片流程** | `半按（引走 p7 抢回）→ 守护恢复（<1s）→ 全按（用 LUT1 渲染）` | 依赖实验 E2/E4 |
| **L3 终极（G4 后）** | 把自定表写进 p7 档位池 → p7 自己 load 我们的表，永不抢回 | 等 U4→U5→G4 |

★ L2 的关键前提：**"全按拍照"自身不触发重载**（若触发，则 L2 只在"全按后下一张"有意义）。
这正是实验 E2 要回答的问题——**在结果出来前，文档不承诺"单张必定带 LUT"**。

## 4. `lutsentinel` 设计（已编译：`test_server/lutpipe/lutsentinel.arm`）

```
用法: lutsentinel.arm [--sel 1] [--fmt 1] [--cbcr 0] [--interval 500] [--count 1200] [--quiet]
```

| 项 | 设计 |
|---|---|
| 检测 | 每 `--interval` ms 读一次 `+0x004`（/dev/drime5_ep mmap，与 epmc 同法）；`(cfg>>4)&3 != 目标` ⇒ 抢回判定 |
| 恢复 | 调官方 `d5_ep_3dlut_op_init(sel,fmt,cbcr)` —— 只写 Cfg |
| 诊断 | 恢复时打印 p7 写的**表地址**（`+0x00c`）——可直接看出它选了哪个档位表 |
| 安全 | nice(19)；间隔下限 100ms；连续 3 次读失败退出；`--count` 到点退出（默认 ~10 分钟）；1 秒内 ≥5 次恢复打 ★ 告警 |
| 输出 | 安静模式仅恢复时一行；`#N` 恢复计数 |
| 集成 | `lutpick.sh sentinel start|stop|status`（setsid 后台 + pidfile + 日志）；`deploy_luts.py` 已含推送 |

**前置与配套**：
- 表须以 `--ch1`（sel=1）装载：`lutpick.sh apply <名> --ch1` —— 守护只改 Cfg、不重灌表；
- 若未用 `--ch1`（表在 LUT0），守护无意义（p7 会继续把 LUT0 覆盖）。

## 5. 实验矩阵（并入 U6 波次；判据写死）

| # | 实验 | 动作 | 判据（写死） |
|---|---|---|---|
| **E1** ★ | **sel=1 首验（方案存活判据）** | `lutpick apply <identity> --ch1`（先 dry 后真做）→ 看取景器 | ① 中性正常 ⇒ **LUT1 接入主链，方案成立**；② 无变化 ⇒ LUT1 未接主链，方案降级；③ 花屏 ⇒ 立即 `opinit 0` / `lutload restore`，方案停 |
| **E2** | 全按是否触发重载 | 守护运行中：不半按直接全按拍 1 张；查守护日志是否记录抢回（含时间） | 无抢回记录 ⇒ 全按不重载（L2 可行）；有 ⇒ 记录时机（按下/存片） |
| **E3** | 半按+守护恢复 | 半按对焦（已知触发抢回）→ 观察守护恢复耗时 | 日志恢复间隔 <1s ⇒ L2 时间预算成立 |
| **E4** | 拍片流程端到端 | `半按 → 等 1s（守护恢复）→ 全按` 拍 1 张 → 成片 vs 取景器 | 成片带风格 ⇒ **L2 闭环**（操作法成立）；否则记录负结论 |
| **E5** | 守护负载 | 守护跑 10 分钟，期间 normal 拍摄 | 相机不卡、loadavg 平稳 ⇒ 可常驻；异常 ⇒ 调大间隔 |

**回退总预案**：`lutpick off`（identity）→ `lutload.arm restore` + 半按 → 重启。任何一步异常都停。

## 6. 风险与降级路径

| 风险 | 概率 | 降级 |
|---|---|---|
| E1 显示"无变化"（LUT1 未接主链） | 中 | 回单通道 + **重灌守护**（lutsentinel v2：发现被抢回时调 lutapi load 重灌；含 cmasafe 缓存落点） |
| E1 花屏 | 低 | 方案停；记录；回到 L0 纪律 + U6 原判据 |
| p7 开始"每帧"重载（高频抢回） | 低 | 守护告警；调大间隔；接受"贴近实时"的闪烁；等 L3 |
| 守护与 lutapi 并发调用 | 低 | 纪律：apply 时先 `sentinel stop`，装表后再 `start`（runbook 已按此排列） |
