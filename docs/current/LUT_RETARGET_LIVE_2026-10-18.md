# 运行态换表闭环：改登记表 + 写槽 + 负片判决（2026-10-18）

> **一句话**：不刷机、不改固件，改 **1 个 4 字节登记表项** 并往 **空闲槽** 写 19,712 字节，半按触发重载后取景器出现**明确的负片画面**；两条写入均可双向回滚，备份与镜像逐字节一致。
> **前置**：[Cfg 位定义与登记表回读](LUT_REGTAB_READ_2026-10-18.md)（22/22 与 16KB diff=0）。
> **边界**：只验证 View（取景）链路；Still（成片）、重启后的持久性、非 A2 固件均未验。

## 0. 结论（四层全部实证）

| # | 命题 | 证据 | 强度 |
|---|---|---|---|
| 1 | 登记表所在页 **可写**（`/dev/mem` `O_RDWR`+`PROT_WRITE`） | `probe` 写回原值，回读一致，16KB 内 stray=0 | ★★★ |
| 2 | p7 **每次 Load 都重新读登记表项** | 改项后 `cfg` 与 `sel` 全程不变（`0x100`/SelLUT=0），仅 `load_addr` 由 `0x81115200` 变为被写入的地址 | ★★★ |
| 3 | 改 `View4[3]` 一个 word ⇒ **硬件 Load 源真的改变** | `load_addr: 0x81115200 → 0x81119f00`（半按后）再 `→ 0x810fd100` | ★★★ |
| 4 | 写入槽内容会被**实际渲染** | 槽内 4913 项全部 `255−R` 反相后，取景器出现明显负片（用户目视确认） | ★★★ 目视 |
| 5 | **Still（JPEG 成片）同样消费该表** | `Still6` 六项全指负片槽 + 拍一张 → 成片 `SAM_0044.JPG` 为负片（View 侧仍指原厂 A17，取景器正常） | ★★★ 文件目视 |

⇒ **「换表」的最小闭环 = 写表进槽 + 改登记表 + 一次重载**。不涉及刷机、不改 p7 代码、不用 CMA、不用守护、不抢时序。
⇒ 且 **View 与 Still 两条链路可独立重定向**：改 `View4` 只影响取景，改 `Still6` 只影响成片。

> **2026-10-18 10:20 补充**：Still 判据已闭环。§5 原第 1 条「Still 是否跟随」现已验证为**跟随**，见 §1.3。

## 1. 实验链与数据

全部在同一次相机会话内完成（相机 192.168.0.106，App 未重启，A2 固件 `712c6fd0…`）。

| 步 | 动作 | 机器判据 |
|---|---|---|
| 0 | `status` 基线 | `VIEW4 = 810fd100 81101e00 81106b00 81115200`；`onoff=1 cfg=0x100 pulse=0 load=0x81115200` |
| 1 | `probe`（no-op 写回 `0x81115200`） | 写映射成功；回读一致；窗口 stray = 0 |
| 2 | `patch`（`View4[3]` → A18 `0x81119F00`） | 字内变 1 字节；stray = 0 |
| 3 | 用户半按一次 | `load_addr → 0x81119f00` ✅；**画面无可辨变化** |
| 4 | `patch12`（→ A12 `0x810FD100`） | 字内变 1 字节；stray = 0 |
| 5 | 用户半按一次 | `load_addr → 0x810fd100` ✅；画面"整体变亮/偏凉"，**无色偏** |
| 6 | 写负片表进 A18（19,712B，先备份） | 源与现值差 14,662 字节；`READBACK mismatched bytes = 0` |

### 1.1 第 3 步为什么"看不出"

各槽与 A17 的逐字节差异（19,712B，含尾部 60B pad）：

| 槽 | 差异字节 | 占比 | 最大偏差 | 平均偏差 |
|---|---:|---:|---:|---:|
| A12 标准 | 13,801 | 70.0% | 97 | 9.34 |
| A14 电影 | 13,810 | 70.1% | 97 | 9.50 |
| A13 黑白 | 7,792 | 39.5% | 29 | 1.93 |
| **A18** | **806** | **4.1%** | **8** | **0.08** |
| A19 | 856 | 4.3% | 21 | 0.09 |

A18 与 A17 几乎同表 ⇒ 换过去视觉不可辨。**这不是"硬件没消费"，是判据选错了表**。

### 1.2 A12 的色点预测与实测对照

| 格点 | A12 | A17 | Δ |
|---|---|---|---|
| 中性灰 128 | (128,128,127) | (128,128,128) | (0,0,−1) |
| 暗部 32 | (56,24,48) | (33,31,32) | (+23,−7,+16) |
| 暗部 64 | (112,42,95) | (66,61,64) | (+46,−19,+31) |
| 高光 240 | (189,214,228) | (206,207,240) | (−17,+7,−12) |

用户观察"整体变亮、感觉偏凉"，与"暗部大幅提亮、高光转青"方向一致；但用户同时报告"颜色没偏"，故当时**不采信为人眼证据**，直接升级到负片判决。这个选择是对的：负片结果无歧义。

### 1.3 Still 链路（10:11–10:20）

`Still6 @0x80382C5C` 是独立于 `View4` 的六项登记表，由 `0x80382B30` 的条件逻辑（`(100·S−8000)/16` + 阈值）选取。为避免猜"Still 走哪个分支"，把**六项全部指向同一槽 A18**：

| 步 | 动作 | 机器判据 |
|---|---|---|
| 1 | `still-status` 基线 | `81119f00 81115200 8111ec00 8110b800 81106b00 81110500`（与 T4 一致） |
| 2 | A18 写入负片表 | 差 14,662 字节；`READBACK mismatched = 0`；备份 `a18_neg_orig.bin` |
| 3 | `still-set` 六项 → `0x81119F00` | `READBACK ok`；字内 7 字节；stray = 0 |
| 4 | 用户拍一张（取景器此时正常，`View4[3]` 仍指 A17） | `SAM_0044.JPG` **成片为负片** |
| 5 | `still-restore` + 槽还原 | 六项回原厂；`READBACK mismatched = 0`；`load_addr` 自动回 `0x81115200` |

**关键对照**：拍照时 `View4[3] = 0x81115200`（原厂肤色表）⇒ 取景器正常，而成片负片。说明 **Still 走的是 `Still6` 而非 `View4`**，两条链路互不干扰，可分别重定向。

**这与 10-09 的 E4 不矛盾**：E4 把表放进 **LUT1**，而 Still 的 `_load` 用 `sel=0`（LUT0），bank 不匹配，成片必然不跟随。本次改的是 **LUT0 的源地址**（`Still6` 六项），故成片跟随。E4 的"成片直灌无效"应改写为"**LUT1 直灌对成片无效**"。

## 3. 可逆性与还原核验

- A18 写入前的备份 `a18_orig.bin` 与原厂镜像切片 `[0x8AFCC0, 0x8AFCC0+19712)` **逐字节相同**（md5 `4c0cc78cfa90ea39a78f42450829f7cb`，19,712B）
  ⇒ 备份可信，且反证"运行时槽内容 == 镜像原内容、未被 p7 改写"
- 回滚后：登记表 = `0x81115200`；A18 回读 `mismatched = 0`
- 两条写入都是**内存操作**，断电即回原状；不写分区、不写固件
