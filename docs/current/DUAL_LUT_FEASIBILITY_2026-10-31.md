## 1. 硬件判决

### 1.1 只有一级

p7 对 3DLUT 块的全部写入（`P7_3DLUT_PATHS` §4.2 全镜像 grep）：

```
+0x000  OnOff
+0x004  Cfg      bits[1:0]=SelCbCr_ch  bits[5:4]=SelLUT  bit8=LUT0 fmt  bit12=LUT1 fmt
+0x008  Pulse    bit8=写方向(rw_Start=1)  bit4=读方向(rw_Start=2)
+0x00c  LUT0 数据地址
+0x010  LUT1 数据地址
```

**五个寄存器，没有长度、没有维度、没有第二级。** 长度硬编码在 DMA 控制器里（4913×4B）。

### 1.2 LUT0/LUT1 是 bank，不是串级

`libudd5` 写序列（`sub_3a888`）：

```c
_udd_ep_3dl_reg_OnOff(1);
_udd_ep_3dl_reg_Acc_OnOff(0);  _udd_ep_3dl_reg_Acc_OnOff(1);   // 开访问窗口
switch (c->mode_at_0x10) {
case 0:  SetAddress(cfg->f8, c->f4); SetColorFormat(c->f8, …); break;   // → +0x0c
case 1:  SetAddress(cfg->fc, c->f4); SetColorFormat(cfg->fc, …); break; // → +0x10
case 2:  /* 两个地址都设 */                                              break;
}
rw_Start(1);   // bit8 脉冲 = 一次 DMA
```

`SelLUT` 写的是 `Cfg bits[5:4]`，2 bit 宽，值域 `{0,1,2}`，语义 = "选哪张表"。**一次 DMA 只搬一张表**，`case 2` 只是把两个地址寄存器的入口都打开，不是"跑两遍"。

### 1.3 三条软件路径共用同一块硬件

`CBackend_3dlut_View` / `_Still` / `_CS` 三个 vtable 都落到 `0x2082b000`。ISP 链上**没有第二个 3D LUT 阶段**可以挂第二张表。

⇒ **要在设备上做"两张表顺序作用"，只能改 p7 在链里插第二个 pass**，而链上没有这个位置。这不是"没找到"，是"不存在"。

## 2. 三种"分离"的技术含义

| 形态 | 两张表在哪 | 是否串联 | 硬件可行 | 用途 |
|---|---|---|---|---|
| **A 设计期分离** | PC 浮点域 | 是（但只在内存里） | ✅ 无关硬件 | 独立调 tone / color；最终合成单表 |
| **B 双槽分发** | View4 槽 + Still6 槽 | 否（各走各链路） | ✅ 已实证（10-18） | 预览表 ≠ 成片表 |
| **C 双 bank 热切** | LUT0 SRAM + LUT1 SRAM | 否（互斥生效） | ◐ 待验（§4.2） | A/B 秒切、零重载 |

"级联"（真·两张表一前一后作用在同一像素上）**不在可行集里**。

## 3. 数值实验：两级分解到底损失多少

### 3.1 方法

- 取 `looks/` 下的 native 表（CrCbY-BT601-full-v1，有 `encoding.json` 哈希校验）
- 只统计**合法输入格点**（`ycc_to_rgb(clip=False)` 三通道都在 [0,255]）：**971 / 4913 = 19.8%**
  （其余 80.2% 是 sRGB 域外的外推填充，算进去会污染统计——上一版 `LUT_PHYSICAL_FILM` 的"80.5% 越界"在此复现）
- 分解：
  - **T 级**：只改 Y，曲线取中性轴（`Cr=Cb=128` 的 17 点响应），色度直通
  - **C 级**：只改 CbCr。分两种构造：
    - `naive`：C 表直接在原始格点上取 f 的色度（用错 Y 位置）
    - `compensated`：C 表在 **T 的输出域**重建（`C(y) = f(T⁻¹(y))`），理论上应精确复现 f
- 误差 = RGB 域三通道**最大绝对误差**（0–255 尺度）

### 3.2 结果

| 表 | Y 的色度耦合（同亮度跨色度 std） | naive 均值 | **compensated 均值** | compensated p95 | max |
|---|---:|---:|---:|---:|---:|
| fuji_velvia50 | **5.3** | 9.5 | **7.2** | 20.3 | 34 |
| brand_teal_orange | 7.9 | 12.1 | **8.2** | 24.2 | 68 |
| kodak_portra400 | 12.5 | 26.1 | **14.8** | 40.4 | 91 |
| fuji_pro_neg_std | **18.7** | 31.7 | **26.1** | 68.7 | 92 |

### 3.3 读法

- **补偿式比朴素式好 20–45%**，但**没有一项进入可接受区**（摄影上 <3 才算无损）
- 损失来源是硬性的：C 级的 Y 分辨率仍只有 17 级，而色度对亮度的依赖很强（spread 24–40/17 级 ≈ 每级 2.4）
- **表的"亮度-色度耦合度"直接决定分离代价**：Velvia 类（主要做色相旋转）耦合低、可分离性最好；Portra / ProNeg 类（负片密度混合）耦合高、分离必然坏

⇒ **结论：17³ × 2 的串联在强风格表上不成立。** 想要两级，必须两级都在浮点域，最后只落地一张表（即形态 A）。

## 4. 可行的两条路

### 4.1 形态 B：双槽分发（已具备，10-18 实证）

| | View 链路 | Still 链路 |
|---|---|---|
| 登记表 | `View4 @ 0x803837F0`（4 项） | `Still6 @ 0x80382C5C`（6 项） |
| 切换方式 | 改 4 字节项 + 半按 | 改 4 字节项 |
| 表来源 | 槽池任选（103 个 0x4D00 槽） | 同左 |

**两张表可以完全不同、同时生效、互不干扰。** 这是唯一"真·双 LUT"的现有形态。

用途（需明确 UI 语义）：
- 预览表 = 保守版（低对比、暗部不死黑，取景器看得清）
- 成片表 = 完整版（打印级曲线）
- 代价：**所见非所得**，必须告诉用户"取景器只是预告"

### 4.2 形态 C：双 bank 热切（待验证，建议先做）

前提事实：
- p7 只写 `+0x00c`（LUT0 地址），**不碰 `+0x010`（LUT1）** ⇒ LUT1 内容装一次就常驻
- p7 半按会把 `SelLUT` 写回 0（E3 守护记录的 6 次"抢回"就是这件事）

**待验证的唯一问题**：只写 `Cfg bits[5:4]`（不触发 DMA）能否立即切换画面？

- 若**能** ⇒ 两张表常驻，写 4 字节即切换，A/B 对比零延迟（摄影调色最实用的功能）
- 若**不能** ⇒ 切 bank 必须伴随一次 load（1.6 MB/s × 19.7 KB ≈ 12 ms，仍可接受）

E1（10-09）观察到 `sel=1` 后 `Cfg=0x1110` 且画面变化，但当时 `op_init` 后面还跟了 `load`，**两个变量没分离**。这是本轮唯一值得上机的实验，零风险（只写 Cfg，可立即写回）。

### 4.3 形态 A：设计期两阶段（当前 `film_physics` 已在做）

neg（负片）→ print（相纸）两级，**在 numpy 浮点域复合**，最后一次性量化成 17³ 单表。

这是唯一精度无损的两级结构。它回答的是"设计上要不要分开"，不是"设备上能不能分开放"。
