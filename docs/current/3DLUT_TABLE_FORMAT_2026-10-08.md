## 0. 一句话

**表格式 = 4913 项 × 4 字节 `{R,G,B,pad=0}`（24-bit RGB + 空字节），索引 `((B*17+G)*17+R)*4`（R 最快），槽步长 `0x4D00`。**

- `p7_full.bin` **文件内**就有完整的表池：**Block A（20 槽）+ Block B（22 槽）**，可离线逐字节读取。
- 其中「**标准**」表与归档里运行时 `0x810FD100` 的采样**逐字节一致** ⇒ 打通了「镜像内表池 ↔ 运行时缓冲」。
- **旧「16-bit 三通道交织」假说被否**（若为真，每 4 字节的第 4 字节不可能恒为 0）。
- ⇒ **P1 的「save_lut dump 是唯一直接路径」表述作废**；dump 降级为**交叉验证**手段。

## 1. 表格式（逐字节自证）

### 1.1 原始字节（`p7_full.bin`，VA = 文件偏移 + `0x80000000`）

| 槽 | 前 16 字节（hex） | 解读 |
|---|---|---|
| `0x808847C0` | `08 08 10 00 · 17 08 10 00 · 26 08 10 00 · 35 08 10 00` | R 步进 +15/16，G=8 固定，B=16 固定，pad=0 |
| `0x8088E1C0` | `01 01 01 00 · 10 01 01 00 · 20 01 01 00 · 30 01 01 00` | R = 16 进制的 1,16,32,48…，pad=0 |
| `0x80897BC0` | `00 00 00 00 · 10 00 00 00 · 20 00 00 00 · 30 00 00 00` | **纯 identity** |
| `0x80892EC0` | `15 00 0d 00 · 23 00 0c 00 · 31 00 0b 00` | **标准**（见 §5） |

⇒ 每项就是 `{R, G, B, 0}` 四字节；第 4 字节（pad）**在整个表内恒为 0**（见 1.2 的自证）。

### 1.2 三条独立自证

1. **pad 恒零**：对 4913 项逐项检查 `byte[4i+3] == 0`，命中表中 **100% 成立**（Block A/B 共 42 个槽全部通过）。
2. **单轴展开**：沿 R 轴（索引 `r`）、G 轴（`17g`）、B 轴（`289b`）分别取 byte0/byte1/byte2，三条 ramp 各自连贯；
   例如 `0x8088E1C0` 的 R-ramp =
   ```
   1, 16, 32, 48, 64, 80, 96, 112, 128, 144, 160, 176, 192, 208, 224, 240, 254
   ```
   ⇒ 输入 17 个**等距**电平（0,16,32,…,240,255），输出近似 identity（0 端抬到 1、255 端收到 254）。
3. **中性点**：`diag(i)=((i,i,i))` 对 identity/near-id 表在 i=8 处 = `(128,128,128)`（严格中性）。

### 1.3 索引与电平

```
N            = 17³ = 4913 项
offset(i)    = ((B*17 + G)*17 + R) * 4      // R 变化最快
item         = { R_out, G_out, B_out, 0 }
输入电平      = 17 个：0, 16, 32, …, 240, 255（step 16）
占 用        = 4913 * 4 = 19652 字节
```

**索引公式的独立佐证**：`p7_full.bin` 内存在 32-bit 常量 `4913`(=17³) 于 `0x94011c, 0x954fac, 0x95524c`（3 处）——均位于**字面量池/数据段**，不在任何函数体内。

## 2. 槽布局与尾部填充

```
每槽 = [ 表 19652B ] [ 填充 60B ]          ← 合计 19712 = 0x4D00
填充 = 最后一项 ×3（12B） + 48×0x00
```

实测（`0x808847C0 + 19652` 起 60 字节）：
```
b6 b6 fe 00 | b6 b6 fe 00 | b6 b6 fe 00 | 00×48
```
⇒ 「最后一项重复 3 次 + 48 个 0」是本格式的**强指纹**，可作槽边界判据。

## 3. 镜像内表池（Block A / Block B）

锚点经 `0x80892EC0 % 0x4D00 = 0x6C0` 反推确定；两块的跨度都**精确等于步长的整数倍**：

| 块 | phase | VA 范围 | 跨度 | 槽数 |
|---|---|---|---|---|
| **A** | `0x6C0` | `0x808592C0 … 0x808B49C0` | `0x5B700` = **19.000×0x4D00** | **20** |
| **B** | `0xAC0` | `0x808B9AC0 … 0x8091EBC0` | `0x65100` = **21.000×0x4D00** | **22** |

### 3.1 Block A（20 槽，phase 0x6C0）

前 12 槽以 **3 循环**重复：`[lift(8,8,16), lift(16,16,16), near-id(1)]` × 4，随后：

| VA | E0 =(R,G,B)@(0,0,0) | 类型 |
|---|---|---|
| `0x808592C0` | (8, 8, 16) | lift 黑位、蓝影 |
| `0x8085DFC0` | (16, 16, 16) | lift 黑位、均匀 |
| `0x80862CC0` | (1, 1, 1) | near-identity |
| …（×4 循环）… | | |
| `0x80892EC0` | **(21, 0, 13)** | **标准** |
| `0x80897BC0` | (0, 0, 0) | **identity** |
| `0x8089C8C0 / 0x808A15C0 / 0x808A62C0` | (21, 0, 13) | **标准** ×3 |
| `0x808AAFC0 / 0x808AFCC0 / 0x808B49C0` | (0, 0, 0) | identity ×3 |

### 3.2 Block B（22 槽，phase 0xAC0）

前 12 槽为 `[lift8/16, lift8/16, lift16, lift16, near-id, near-id]` × 2，后 10 槽严格交替：

```
0x808F36C0 标准 | 0x808F83C0 identity
0x808FD0C0 标准 | 0x80901DC0 identity
0x80906AC0 标准 | 0x8090B7C0 identity
0x809104C0 标准 | 0x809151C0 identity
0x80919EC0 标准 | 0x8091EBC0 identity
```

### 3.3 假设（待上机证伪，勿当结论）

- **A / B 两块可能对应 LUT0 / LUT1 两个数据源**——寄存器 `+0x004` 确有 `bit8=SetColorFormat_LUT0`、`bit12=SetColorFormat_LUT1`（见 `3DLUT_API_GUIDE`）。
- 两块内「标准 ×N + identity ×N 交替」符合「**4 静态档 + 24 动态档**」的成对占位（`FUN_0009a408` 的 24 指针 + `FUN_0009a3e8` 的 4 指针）。
- ⇒ **精确的槽↔档位命名必须靠上机 dump**（见 §7 遗留）。

## 4. 与运行时地址的桥接（★ 关键）

三条独立证据把「文件内表池」与「运行时缓冲」连起来：

1. **步长同一**：
   - 4 个静态档缓冲 `0x810FD100 → 0x81101E00 → 0x81106B00 → 0x81115200`，相邻差 **`0x4D00 / 0x4D00 / 3×0x4D00`**。
   - MCB 池 `0x813D8800 / 0x813DD500 / 0x813E2200 / 0x813E6F00` 相邻差 **`0x4D00`**。
   - ⇒ `0x4D00` **确实**是 3D LUT 槽步长，而非巧合。
2. **内容同一**：归档 `EP_3DLUT_WRITE_EXPERIMENTS` 记的运行时 `0x810FD100` 前 8 字节 `15 00 0d 00 23 00 0c 00`
   **逐字节等于**文件内 `0x80892EC0` 的前 8 字节 ⇒ 运行时「标准」= 文件 `0x80892EC0`。
3. **常量佐证**：`0x4D00`(=19712) 以 32-bit 常量出现于 `0x9c9084, 0xa3674c, 0xa36efc, 0xa5cbbc`（4 处，均在字面量池）。

> **注意**：运行时缓冲 `0x810FD100` 的地址**超出文件**（`0x810FD100-0x80000000 = 0x10FD100 > 0xC40000`），
> 归档「表数据不在文件里」**对那 4 个运行时地址仍然成立**；但文件在 **`0x80859xxx–0x8091xxxx` 另存了一套表池**。
> ⇒ 两者是「**模板 / 副本**」关系，不是同一块内存。
