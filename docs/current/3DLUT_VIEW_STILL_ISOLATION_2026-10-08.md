# View / Still 隔离性与「显示正常 + 成片有效」的解法（2026-10-08）

> ⚠️ **2026-10-18 文档清理：本文结论已被取代。** 文中「View 与 Still 共用缓冲池 ⇒ 软件层无法隔离」已**部分推翻**：池确实共用（`View 4 档 ⊆ Still 18 档`），但三张登记表是分开的 —— 改 `View4` 只影响取景、改 `Still6` 只影响成片，2026-10-18 实机实证。
> 现行结论见 [`LUT_RETARGET_LIVE_2026-10-18.md`](LUT_RETARGET_LIVE_2026-10-18.md)。


> 问题（木一）：**已确定 View 与 Still 不走同一条线，如何保证 LUT 在正常显示的前提下，且拍照成片有效？**
> 本篇用**穷举证据**回答：这个问题的前提需要被修正 —— 两条线**软件层面无法隔离**，
> 而"分离"本身**不是目标**。真正缺的是**表格式**。
> 附：本次新发现一条 **dump 内置表**的通道（save_lut），是解开表格式最直接的路径。
> 全程离线，未触碰相机。

## 0. 一句话结论

1. ★★★ **`View 4 档 ⊆ Still 可达集`，View 独有 = 空**（§1 穷举证据）
   ⇒ **在不改 p7 的前提下，"让两条线各走各的表"不可能**。
2. ★★ **「取景器花屏」的根因不是"挂错线路"，而是"表格式未知"**。
   ⇒ 表格式一旦正确，**View 与 Still 共用同一个池反而是优点**：一张正确的表放进档位槽，
   取景器正确 + 成片正确 = 真正的所见即所得。
   ⇒ **所以目标不是"分离两条线"，而是"解出表格式"。**
3. ★★★ **本次新发现**：p7 自带 **save_lut 通道**（把硬件里的表读回 DDR），
   且**目标地址由调用者指定**（`0x179520` 的 r0）——
   而 p7 能访问 Linux CMA ⇒ **可以在 Linux 侧读到内置表的原始字节**，
   不需要 `/dev/mem`、不需要读 p7 内存、不需要重刷固件。
4. **交付态有两条**：正式解 = 解表格式（所见即所得）；保底解 = 软件后处理（取景器不动）。

## 2. 为什么"分离两条线"是伪目标

| 如果强行分离 | 后果 |
|---|---|
| View 用内置表、Still 用我们的表 | 取景器正常，**但成片按未知格式偏色** ⇒ 拍一堆废片，且**当场看不到** |
| View 用我们的表、Still 用内置表 | 取景器花屏（**唯一有效反馈被浪费**），成片无效果 |
| 只改"Still 独有"的 14 个槽 | ✗ 不存在这种隔离 —— Still 仍会选到 View 的 4 个档 |

★ **关键认知**：花屏 **不是"线路选择"问题，是"表格式"问题**。
　表格式正确时，共用池 = **所见即所得**（这是优点）；表格式错误时，**无论挂哪条线都偏色**。

⇒ **正确的问题陈述应该是**：
> 如何解出 3D LUT 的表格式，使得一张自定义表放进档位槽后，取景器与成片同时正确？

## 3. ★★★ 新发现的攻坚手段：save_lut 通道（dump 内置表）

### 3.1 通道结构（静态实读）

```
0x179520  save 对外封装
  ├ 校验：r0(目标地址) != 0 且 第 5 参(sp+4) != 0 且 未占用（否则返回 -1）
  └ b 0x1794a8                        ← 尾调用
       └ FUN_0017b570(8)              ← 加锁（8 = Save 资源）
            └ FUN_00179384(dest, sel, fmt, ptr)
                 └ FUN_004a5e30(&desc)  mode=2
                      ├ 写 +0x010 = dest        ★ Save 目标地址
                      └ 写 +0x008 bit4 脉冲     ★ 触发 3DLUT → DDR 搬运
```

**QEMU 实测对照**（`FUN_00179384(0x94000000,0,0,0)`）：
```
[0x2082b000] <- 0x00000001
[0x2082b008] <- 0x00000000
[0x2082b008] <- 0x00000001
[0x2082b010] <- 0x94000000      ★ Save 目标地址 = 调用者给的
[0x2082b004] <- 0x00000000
[0x2082b008] <- 0x00000011      ★ bit4 置位（Save 启动）
[0x2082b008] <- 0x00000001      ★ bit4 清除（脉冲结束）
```

### 3.2 为什么这条通道能解开表格式

| 约束 | 是否被绕过 |
|---|---|
| Linux 读不到 p7 内存（`/dev/mem` Bad address） | ★ **绕过**：不需要读 p7 内存 |
| Linux 写不到 p7 内存 | ★ **绕过**：只读，不写 |
| 需要重刷 p7 固件 | ★ **绕过**：走 p7 自带的官方 save 路径 |
| 需要知道表格式才能 dump | ★ **绕过**：dump 是"照抄字节"，**不需要懂格式** |

**充要条件只有一条**：`dest` 指向一块 **Linux 侧可读、p7 侧可写** 的内存。
→ **Linux CMA（`0x94000000–0xA6000000`）正好满足**（p7 identity 映射 4GB，见 `3DLUT_DEEP_DIVE` §6）。

⇒ ★★★ **执行方案**：
1. Linux 侧在 CMA 分配一块 ≥ `0x4D00 × 2` 的缓冲，取物理地址 `P`（例如 `0x94000000`）
2. 触发一次 p7 的 `save_lut(dest=P, sel=0)`，把内置档位表读回
3. Linux 侧读 `P` 起的 `0x4D00` 字节 ⇒ **内置表的原始字节**
4. 对比"标准档 vs 黑白档 vs 电影档 vs 肤色档"的差异 ⇒ **直接解出索引/通道布局**

**这是 7 张自造表全部失败之后，第一次有机会看到"正确答案长什么样"。**

### 3.3 唯一待解问题：如何从 Linux 触发 save_lut

`0x179520` 的直接调用者尚未定位（它在 `0x1794a8`–`0x1795ec` 之间的 Ghidra 未识别区）。
已知线索：
- MCB 侧另有入口：`FUN_003fb4cc`（构造 `{2, b[0x4d], 0xff, 0xff, b[0x4e], 0xff}` → `FUN_004b7a40`）
  ← 由 `0x3fb5f8` 调用（同属 `0x3fbxxx` MCB 族）
- MCB 通道**实测是通的**（`st cap iqr` / `st cap capdtm` 均能工作，走 SHELL_COMMAND `0xb6`）

⇒ 下一阶段静态任务：**定位 3DLUT save 的 MCB 命令号**（在 68 条命令表里找 PRD_ / SYS_ 域的对应项）。

## 4. 三条路线 + 优先级

| 路线 | 做法 | 显示 | 成片 | 前置 | 判定 |
|---|---|---|---|---|---|
| **R1 解表格式** | 表格式解出 → 正确表放进档位槽（两路共用） | ✅ 正常 | ✅ 有效 | 表格式（save 通道可攻） | ★★★★★ **正式解 / 所见即所得** |
| **R3 软件后处理** | 取景器完全不动；成片在 Linux 侧做 LUT | ✅ 不动即正常 | ✅ 有效 | 无（`ksfilm.arm` 已跑通，跨环境逐字节一致） | ★★★★ **保底解 / 今天可做** |
| R2 改 p7 分离池 | 改 Still 选择器常量 → 指向独立池 | ✅ 正常 | ⚠️ 仍偏色 | 重刷 p7（G4 未开）**+ 仍需表格式** | ✗ **伪解**：没绕开表格式，只是把偏色藏进成片 |

★ **R2 为什么是伪解**：它把"取景器可见的偏色"变成"成片不可见的偏色"——
　反馈回路被切断，你会拍一堆废片才发现。**这是最坏的组合。**

## 5. ★ 开发期策略：用 View 当探针，用 Still 当验收

由于 `View ⊆ Still`，**同一张表对两路都生效**，这带来一个高效率工作流：

| 阶段 | 平台 | 原因 |
|---|---|---|
| **格式探索** | **View** | ★ 实时反馈：改表 → 取景器**秒级**可见，不用拍照、不用读卡 |
| **格式确认** | View | 取景器颜色正常 ⇒ 格式对了 |
| **最终验收** | **Still** | 拍一张看成片（最严判据：照片是否真被处理） |

⇒ **顺序**：先在 View 上调对格式（允许开发期暂时花屏）→ 格式正确后取景器恢复正常
→ **同一张表自动对 Still 生效**（共用池）→ 成片自然有效。

★ **交付态**（表格式正确后）：显示正常 + 成片有效，**同时满足**。
★ **探索期**（格式未对）：显示会异常 —— 这是开发的必经阶段，不是交付缺陷。
