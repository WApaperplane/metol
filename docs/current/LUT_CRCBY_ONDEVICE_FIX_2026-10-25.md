# NX500 LUT 原生编码修复：2026-10-25 实机结果

## 已完成的结果

相机 `192.168.0.102`、NX500 v1.12，已经用受控 JPEG 对照确认并修复 **RGB 设计表直接写入 CrCbY 原生槽** 的回归。

- 相机原有 **48 个名称保持不变**：47 张重编码，identity17 原字节保留；没有补回用户删掉的表。
- 最终 **48/48 文件哈希一致**，目录为 48 个无重名 `.bin`；A18 回读与当前 Portra 400 的差异为 **0 字节**。
- 原生黑白探针在取景帧和成片中均保持无彩色；仅压 Y 的探针降低亮度而没有新增绿色；黄、蓝探针分别沿预期方向变化。
- 旧 Noir、Portra 400、Pentax Gold、Classic Chrome 均拍摄了修复前后同场景 JPEG。偏绿/品红现象在正确编码后消退。

- 自定义1原保存值为 `102/100/103/12/11/1/9`，ISP 实际此前为中性；本轮将其保存值也设为 `100/100/100/10/10/10/10`，消除切档/菜单重读旧增益的隐患，并保存原值恢复脚本。

此结果确认了**色彩编码故障的修复**。未把 48 张全部宣称为经过原厂样片测量的胶片复刻；各风格还原程度需要按 [20 个设计方向](LUT_COLORSPACE_REGRESSION_REVIEW_2026-10-25.md#20-个色彩设计方向) 继续评价。本轮没有改动配方参数来掩盖编码错误。

## 生成与检查链路已经同步修复

新增 `tools/lutgen/native_codec.py`，明确分离：

```text
RGB 设计 → 枚举原生 Cr/Cb/Y 网格 → CrCbY→RGB
         → 采样 RGB 设计 → RGB→CrCbY → 原生 .bin
```

`gen_luts.py` 的 `build_rgb()` 仅供设计；`build()` 现在输出原生 Cr,Cb,Y，`write_cube()` 使用标准均匀网格。`looks/encoding.json` 为每张表保存编码类型与 SHA256，元数据/文件不符时拒绝继续解释。

`preview_photos.py`、`audit.py`、`color_def.py`、`cool_probe.py`、`ref_profile.py` 已按声明解码原生表后评估 RGB 色彩。旧的直接改字节工具 `retune_legacy.py` 遇到已声明的原生表会拒绝处理，避免再次把 Cr/Cb 当作 R/G 修改。`lut.sh` 保留已验证的 OLED 分支管理，但撤下“RGB 黑白表偏色证明 OLED 是根因”的错误注释。

原有工作区未提交的配方和代码先备份，再做上述局部修改；没有重置用户工作区。新生成器与修复前 RGB 设计的 **54/54 配方逐字节回放相等**；全量重生成后，已迁移的 **78/78 本地文件哈希不变**。原厂3表与 identity 保持原字节。

验证：

- 新原生编解码与迁移测试 **8/8 通过**，覆盖相机已验红/蓝/灰编码、全节点黑白色度、均匀 cube、元数据哈希拒绝、PC 预览/色彩探针、迁移重复性与原厂保护。
- 初始恢复包的语义检查 **7/7 通过**，其中包含与 19 日 HP5/Fuji400H 实机导出的 ≤2 LSB 对照。
- 修复后全库体检：**70 OK、4 WARN、0 BAD、原厂参考3、反相1**。WARN 为 Cinema/Expired/Faded/Matte 的色调或抬黑设计；当前相机选择中只有 Matte 在这一组，未擅自更改风格或移除。
- Python 语法与 `git diff --check` 通过。

BT.601 full-range 仍是经过方向、无彩色和偏色回归验证的**工作矩阵**，并非完成了 NX500 精确色度/量程标定。
