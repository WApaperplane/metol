## 1. 消费路径（带地址）

### 1.1 完整链条（View 线）

```
[View 入口]  CBackend_3dlut_View::_load = FUN_0011e20c（vtable 0x58385c，消息 0x10000002）
   │
   ├─ 选表（对外 API） FUN_0009A3E8 ── push; bl 0x802AEBD8; b 0x802B03F4
   │      （同类：FUN_0009A3C8 = Still 静态；FUN_0009A408 = 动态 24 档）
   │         ↓ 薄封装（每层 = 「取单例 0x80381A60 → 转发」模式）
   │      0x802B03F4 → bl 0x8029B480 → b 0x8029BAA4
   │      0x8029BAA4 → bl 0x80381A60 → b 0x80381ABC
   │      0x80381ABC → bl 0x80382054 → b 0x80382B30   ★★ 落到「条件选表实现」
   │
   ├─ ★ 条件选表实现 @ 0x80382B30（反汇编要点，见 §1.2）
   │      · 三次取值累加 S（bl 0x802B0000 / 0x802AFF3C / 0x802B0078）
   │      · 计算 idx = (100×S − 8000) / 16（带负数舍入：+15 再 asr #4）
   │      · 条件分支（cmp r6,#1200 / cmp r0,#70）→ 从**表登记**取表地址：
   │           0x80382C5C 或 0x80382C60（Still 静态 6 档表的前两项）
   │      · 状态写入对象 +0xD8/+0xDC/+0xE0/+0xE4/+0xE8（表选择状态）
   │
   └─ 装载  FUN_00179314(table, 0, fmt, 0)   ← 第 2 参 sel=0（LUT0）
            └ FUN_004A5C44 → FUN_004A5E30 → 硬件 {OnOff, Acc, +0x00c←表地址, Cfg, 脉冲}
```

- 单例取用链：`0x80381A60` = `movw r0,#0x2AA8; movt r0,#0x8179; bx lr` ⇒ **返回对象 `0x81792AA8`**；
  同区字面量槽：`0x81792AA0` / `0x81792AA4`（off `0x381A4C/50`），另有 `0x8062C3A0` / `0x803819A4` / `0x81006000`。
- ⇒ 「选表」**不是纯查表**，是**条件计算 + 从登记表取地址**（`0x4D00` 常量在此不参与——它在别处，见 §3）。

### 1.2 条件选表实现要点（`0x80382B30` 摘）

| 指令 | 语义 |
|---|---|
| `bl 0x802B0000 / 0x802AFF3C / 0x802B0078` | 三个分量（累加进 `r6` / 存 `r0`）——**分量语义未定**（候选：亮度/色调/场景权重） |
| `mov r3,#100` → `mul r3,r3,r0` → `sub r3,#8000` → `asr #4` | `idx = (100·S − 8000)/16`（带 `+15` 的负数舍入） |
| `cmp r6,#1200` / `blt` | 阈值 1200 分支 |
| `cmp r0,#70` / `movgt r3,#1` / `movle r3,#2` | 阈值 70 分支（枚举 1/2） |
| `ldrgt r5,[pc,#124]` → `0x80382C5C`；`ldrle … → 0x80382C60` | ★ **条件二选一取表地址** |
| `str r5,[r4,#0xdc]` 等 | 写对象状态（+0xD8…+0xE8） |

> ⇒ 「BV 档位」（12 项表）与「静态 6 档」的**语义**（哪个条件选哪张）留待上机对照（不猜）。

## 3. ★ 源表与运行时池的关系（核心未解）

**四条事实**：

| # | 事实 | 证据 |
|---|---|---|
| A | **镜像内静态池 42 槽**（Block A `0x808592C0`+20 / Block B `0x808B9AC0`+22，步长 `0x4D00`）在**整个镜像内零引用**：既无字面量（池首与全部 42 槽地址），也无配对指令构造 | `p7_pool_refs.py --group static`（字面量 0 / 配对 0） |
| B | **p7 镜像无段表**：`chunk-05.bin` 以 **ARM 异常向量表**开头（`b`×8）；`p7_wrapped.elf` 仅 1 个 LOAD 段（`0x80000000`, FileSiz=MemSiz=`0xB84280`）——**不含**运行时池（`0x810FD100` 超界 0x10FD100 > 0xC40000） | readelf + 头部 hex |
| C | 运行时池**不在 SMA/CMA 区**：`SMA_GET_REGION_START_ADDR` = `0x94000000`(+144MB)、第二区 `0x8f800000`(+72MB) ⇒ 运行时池（`0x810Fxxxx–0x813Exxxx`）属 **p7 地址空间内另一区**（既非 Linux CMA，也非镜像映射段） | `3DLUT_API_GUIDE` §4.1 + `cmasafe` 输出 |
| D | 静态池「标准」与运行时 `0x810FD100` **前 8 字节逐字节一致**（历史归档） | `3DLUT_TABLE_FORMAT` §4 |

**⇒ 唯一自洽的读法**：两者**内容相同、机制无关联**——运行时池的**填充者不在本镜像内**（A+B+C 三条穷举），
而 D 说明「同一份数据被两处登记」。⇒ 填充者候选（**不补猜测**）：

1. **硬件/ISP 侧初始化**（如 LUT 单元内置表经某路径落到该地址）；
2. **分区外组件**（T-Kernel 本体或其他未打包在 `chunk-05.bin` 的组件）；
3. **出厂流程产物**（静态池为「死数据」模板，运行时池由另一路径填充）。

> **注**：10-09 的 A/B 对照（写前非「抢回态」写入不生效）与此相容——说明**该池有独立状态机**，
> 其内容/指针由 p7 内部事件驱动（`+0x00c` 地址寄存器 16 处镜像同步），与「谁填内容」是两个问题。
