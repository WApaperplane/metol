## 1. 三种语义

设基准 B0 = 原厂 A17，两张 look 为 A、B，强度 α、β ∈ [0,1]：

| 模型 | 公式 | 直觉 |
|---|---|---|
| **M1 偏移相加** | `T = B0 + α(A−B0) + β(B−B0)` | 两张表各按自己的强度**贡献偏移**，互不覆盖 |
| **M2 顺层覆盖** | `T = mix(mix(B0, A, α), B, β)` | 先按 α 打 A，再按 β 盖 B（图层 / 松下 opacity 语义） |
| **M3 归一加权** | `T = B0 + (α(A−B0) + β(B−B0)) / max(1, α+β)` | 两张表按强度**加权**，总权重超 1 就归一 |

三者都满足：α=1,β=0 → 纯 A；α=0,β=1 → 纯 B；α=β=0 → 原厂。

### 1.1 溢出（clamp 之前的越界节点数，总计 4,913）

只统计**混合导致的**越界。直接数「输出 Y 贴 0/255」是错的 —— 胶片表本来就把黑白端点压死，`kodak_portra400` 自己有 533 个这样的节点。

| 组合 | 模型 | α | β | Y 越界 | CbCr 越界 |
|---|---|---|---|---|---|
| portra400 × teal_green | M1 | 1.0 | 1.0 | **140** | **144** |
| portra400 × mono_acros | M1 | 0.5 | 1.0 | **454** | 22 |
| portra400 × mono_acros | M1 | 1.0 | 1.0 | **692** | **211** |
| 任意 | M2 | 任意 | 任意 | 0 | 0 |
| 任意 | M3 | 任意 | 任意 | 0 | 0 |

**M1 的溢出只发生在 α+β>1**：只要两者之和不超过 100%，它也是零溢出（这时它和 M3 是同一个公式）。

### 1.2 顺序依赖（A/B 互换后的平均通道差，单位：8 位级）

| 组合 | 模型 | α=β=0.5 | α=1, β=1 |
|---|---|---|---|
| portra400 × teal_green | M1 / M3 | 0.00 | 0.00 |
| portra400 × teal_green | **M2** | **7.06** | **28.28** |
| portra400 × mono_acros | **M2** | **7.55** | **30.16** |

M2 在双 100% 时相当于**换了一张画** —— 用户把 A、B 换个位置，成片就变了，而 UI 上没有任何提示。这是它作为默认语义的致命伤。

### 1.3 关键色读数（α=β=0.5，中灰 / 肤色 / 白点）

| 组合 | 模型 | 灰 128 | 肤色 | 白 245 |
|---|---|---|---|---|
| portra400 × teal_green | M1 = M3 | (132,139,145) | (203,148,118) | (242,243,245) |
| portra400 × teal_green | M2 | (126,131,137) | (196,142,114) | (241,242,245) |
| portra400 × mono_acros | M1 = M3 | (140,140,142) | (185,154,135) | (247,247,247) |
| portra400 × mono_acros | M2 | (132,132,134) | (179,148,132) | (246,246,246) |

差异方向一致（M2 总是更靠近 B），量级 5–7 级 —— 不是误差，是语义差别。

## 2. 为什么 M3 = 现有两个动词的组合

把 M3 拆开。令 `s = min(α+β, 1)`、`r = β/(α+β)`：

```
M_AB(r) = (1−r)·A + r·B                    ← 就是现在的 mix A B r
M3      = B0 + s·(M_AB(r) − B0)            ← 就是现在的 strength · s
```

**两次 `lutmix` 调用，一个新二进制都不用写。** 两个动词（`mix` / `strength`）11-01 就已经在 `lut.sh` 里了。

### 2.1 验证（`test_server/lutpipe/test_dual_strength.py`）

qemu 下真跑两次 `lutmix.arm`，与 Python 参考逐字节比对：

| 检查 | 结果 |
|---|---|
| mix→strength 两步 == 两步参考（6 组 α/β） | 全等 |
| 与理想单步值（`base + s·(mid−base)`）的差 | ≤ 1 级（两次 8 位取整的极限） |
| α+β ≤ 1 时 M3 与 M1 的差 | ≤ 1 级 |
| s=0 必须逐字节回到原厂表 | 通过 |
| s=1000 必须等于纯 mix 结果 | 通过 |

### 2.2 代价

两次调用 = 多一次 19,712 B 的读写。中间表放 `/tmp`（内存，不产生 exFAT 碎片），实际耗时在 ARM 上是毫秒级 —— 对比现有 `apply` 的 0.5 s（`.cube` 转换）完全不是瓶颈。

## 3. UI 怎么摆（720×208 不能多一行）

MIX 态现在只有一条滑杆（强度）。要两个强度，且**不能新增行** —— 按钮行 `y=123/149` 被测试钉死。

方案：**一条滑杆 + 焦点切换**。

| 元素 | 行为 |
|---|---|
| 底部状态行 | `A 60%   B 25%   -> 比例 71% / 强度 85%   退出即应用` |
| 标题 | `LUT / 混合 · A` 或 `· B`，直接标出焦点 |
| 左右键 | 混合态：选 A / 选 B 焦点；其余态：照旧翻页（`ACT_LEFT`/`ACT_RIGHT` 与上下分开绑） |
| 上下键 | 换条目（混合态里也能翻，这是设 A/B 时唯一需要的导航） |
| 滑杆 / 右上拨盘 | 调**当前焦点那个**的强度（拨盘 5%/格） |
| 按钮行四格 | `设为A` `设为B` `应用混合` `退出` |
| 翻页 | 滚条拖动（跨全库最快）、上下键、EV 拨盘、右上拨盘 |

用户看到的还是「两个强度各一根」，内部换算成比例和总强度 —— 换算对用户不可见，但**结果可预测**：双 100% 得到的是两张表的中点全强度，不是死黑死白。

### 3.1 A/B 在哪标 —— 试过搬出去，实机不行，退回来了

曾经把标记搬到浏览态长按（「翻到哪标到哪」听起来最省事），**实机一按就跳**：

> 列表是「选中项居中」的 5 项窗口（`first = selected - win/2`）。手指按下的一瞬间该项被选中，整排立刻平移，手指底下换成了另一条 —— 长按根本对不准，还把原来的「长按进编辑态」挤掉了。

所以定稿是：**长按还给编辑态，A/B 回混合态用按钮设**。原来那个「跨度大不好设」的痛点，靠两件事解决：

| 手段 | 作用 |
|---|---|
| 滚条拖动 | 一次跨全库（68 项 → 700px 轨道，拖到哪算哪） |
| 滚条上 A（绿）/ B（橙）两个刻度 + 列表 `[A]`/`[B]` 前缀 | 跨页也看得见两个端点在哪，不用记 |

**一并删掉的还有左右滑动切项**（原来「滑得远切得快」）：它和「选中即居中」的平移叠在一起，手指刚落下整排就动，再滑一次直接把目标甩掉。删掉之后翻页只剩滚条 + 上下键 + 拨盘 —— 实测够用，而且点选本身也稳了。

### 3.2 必须写进 UI 的一句话

> 两个强度之和超过 100% 时，效果会被等比例压缩（不会叠加到溢出）；**退出混合即应用**。

这不是妥协，是 M1/M2/M3 任何双参数模型都逃不掉的耦合：两张表的偏移向量并不两两正交，同时推满必然要有个"怎么办"。选归一，是因为它唯一可预测。
