# NXUI: Nuklear 相机端菜单与滤镜预览

NX500 1.12 的独立替代界面，使用 Nuklear（MIT）+ 相机现有 X11/Xft，
不链接 EFL。相机继续输出实时取景，界面仅在底部绘制滤镜条。

2026-10-17 在 `192.168.0.106` 真机验证：中文面板可见，取景/按键正常；
用户点选不同配方后确认色彩变化，切换和关闭正常。后台 A2 八条发送返回成功。

- FilmLab：读取现有 95 条配方，触屏切换并保持窗口打开；150ms 停留合并请求。
- 预览命令 `filmlab.sh preview KEY`：跟随当前画面向导栏位，写该栏位与 ISP，
  不执行 `prefman save`。支持9个内置档位及自定义1/2/3，应用后保持原栏位。
- 保存命令 `filmlab.sh commit KEY`：应用成功后保存一次并关闭。
- 普通关闭保留当前预览；不是撤销，也不恢复打开前的槽位。
- 首次修改各栏位前备份原始七项参数到 SD 的 `filmlab/slot-backups/slot-N.txt`。
  “保存并关闭”会保存当前栏位的配方内容；其余栏位不随此切换而改写。
- NX-KS 主菜单：解析现有 `button|...`、`checkbox|...`、`@子菜单`，支持分页。
- 旧功能脚本复用；这些脚本自行弹出的专用工具窗口未在本次改写。
- 空闲阻塞等待，无定时重绘；单后端串行运行，12s 超时处理，关闭时等待正在进行的操作。
  含服务状态的可见菜单页每秒只读刷新一次，状态不变不重绘。
- 触摸移动不重绘，点击仍使用触屏坐标；操作绘制最多10次/秒，窗口暴露复用缓存。
  UI 和它启动的后端以绝对 nice 19 运行，避免继承机身快捷键进程的高优先级。
- 快捷键 `EV+EV` 直接进入新版主菜单；主菜单不再顺带运行含多次全局 `sync` 的
  码率/延时子菜单生成器，只在进入相应子菜单时生成临时文件。配方未变时复用导出表。
- Telnet/FTP 在当前页面独立显示实际监听状态，开关完成后立即刷新；外部开关变化
  在约1s内更新。UI 路径不等待旧弹窗倒计时，启动失败显示部分状态，不误报全开。
- 配方选择/发送/确认/完成均有当前配方提示；栏位切换先读回验证，已完成则立即继续，
  不再无条件等1s。保留 A2 消息150ms间隔及300ms收尾，不压缩已验证的发送节奏。

实际预览依赖本机已验证的 A2 固件、`pwsend.arm` 和 `FILMLAB_PW=1`。
本包不刷固件。本界面目前浏览 PW 配方；不包含 3D LUT 缩略图或 LUT 选择器。
3D LUT 的预览/成片限制继续以原 LUT 管线文档为准。
标准方向键已接入；机身滚轮的 X11 映射尚未实测，不能据此声称滚轮可用。

- **关闭时归还 X 输入焦点**。相机没有窗口管理器，原生菜单的方向键/滚轮是
  X KeyPress，只投给持有输入焦点的窗口。面板打开会抢走焦点，因此关闭时必须
  还给打开前的窗口；关闭请求一出现就卸窗，后端收尾期间不再遮挡取景。
  回归见 `test_focus.py`（隔离 X server，检查焦点精确回到原窗口）。

## 相机使用

安装并启用后，`EV+AEL` 打开滤镜条，原 NX-KS 主菜单入口打开新菜单。
再次触发入口会关闭面板。面板内“菜单/滤镜”可切换两种视图。

```sh
sh /opt/usr/nx-ks/nxui.sh filmlab
sh /opt/usr/nx-ks/nxui.sh menu
sh /opt/usr/nx-ks/nxui.sh disable  # 回到旧 mod_gui 入口
sh /opt/usr/nx-ks/nxui.sh enable
```

更新包解压到 SD 的独立目录，在该目录运行 `sh install_camera.sh --enable`。
安装器先检查全部哈希和当前脚本基线，备份到
`/opt/usr/nx-ks/nxui/backup-20261017`，然后替换六个入口/引擎/服务脚本并加入新程序。
不带 `--enable` 安装时不主动创建启用标记。
本包基线来自该相机；脚本已有其它修改时会拒绝覆盖。

完全恢复原脚本：

```sh
sh /opt/usr/nx-ks/nxui/rollback.sh
```

回退不改当前所选配方。恢复先前槽位需参考试用目录的 `slot9-before.txt`。

## 开发与验证（WSL）

```sh
cd /mnt/e/NXWA/nx500-modding-work/test_server/nxui
bash prepare_dev.sh
bash build.sh
python3 test_engine.py
python3 test_focus.py
python3 verify_display.py
```

开发依赖下载/解压在 `out/deps`，不安装系统包。需要系统已有 GCC、ARM GCC、
qemu-arm-static 和完整相机 rootfs（默认 `/opt/nxks2/rootfs-112`）。
ARM 构建使用相机 glibc 2.13、32位时间 ABI 和仓库现有启动代码。
测试以隔离的 Xvfb 驱动宿主和 ARM 程序，覆盖中文出图、真实点击、请求合并、
串行预览、保存、失败无重试循环、菜单开关和子菜单。
额外覆盖5ms短点击和每组500个移动/暴露/按键事件，核对绘制上限和空闲唤醒。
引擎测试以替身验证预览不落盘、保存、缺后端、写槽失败和后端失败。

优化后真机短测：约6.16s空闲采样中 UI CPU 未增加一个时钟 tick，RSS 3628KB；
自愿上下文切换由旧版61次降为0次。新旧版该段 CPU 均低于测量分辨率，
这些数据只支持减少空闲唤醒，不代表已定位此前卡顿的根因。
相机原生进程同期占约69%–72% CPU，需结合操作时的机身观察判断流畅性。
此前启动优化阶段的用户复验：重启前仍严重卡顿，重启后打开明显加快、操作正常。
该次验收以重启后状态为准；重启前卡顿的根因与长期稳定性尚未确认。

同日响应优化真机短测：标准栏位 Portra400 5.39s → 4.35s、TriX400
5.33s → 4.36s，四次七项 ISP 值全部匹配，测试结束恢复原始栏位参数。
同一服务菜单完成 Telnet/FTP 关闭266ms、开启200ms，无需重新打开菜单。
修复 `busybox tcpsvd` 的进程名为 busybox、旧 `killall tcpsvd` 关闭不到 FTP 的问题；
现在按可执行文件、tcpsvd applet 和21端口精确定位，避免关闭其它 tcpsvd 服务。
本轮响应优化正式安装后，用户确认“状态即时刷新，响应和取景正常”。

`out/` 为可再生构建/测试产物；`package.py` 用已构建 ARM 程序和相机原始脚本备份
生成更新 zip。上游源码和 MIT 许可见 `vendor/`。
